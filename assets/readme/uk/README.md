# Dango

**Нативний редактор для macOS для роботи з агентами програмування.**

Dango збирає код, агентів, які його змінюють, і все довкола них в одному вікні на папку: редактор із мовними серверами й передбаченнями під час редагування, термінали, браузер, Git, CI, налагоджувач і ШІ-чати з Claude, Codex, Antigravity, OpenCode або агентом, вбудованим у програму. Кожен агент працює в тій самій хронології, питає, перш ніж змінювати файли чи виконувати команди, і перед кожним запитом залишає контрольну точку, тож ви можете переглянути й відкотити зроблене повідомлення за повідомленням. Ніщо з того, що налаштовує папка, не запускається, доки ви їй не довіритеся, а текст ззовні надходить агентові з позначкою ненадійного. Диктуйте в редактор і в поле повідомлення, а розпізнавання мовлення може залишатися на вашому Mac. Dango написано на Rust на справжніх елементах керування AppKit, без Electron; він розмовляє 35 мовами й не має телеметрії.

**Ще не випущено.** Перший випуск буде образом диска, підписаним Developer ID і нотаризованим Apple, для macOS 14 або новішої на Apple Silicon та Intel. А доти [зберіть Dango з вихідного коду](#збирання-з-вихідного-коду).

**Знайшли помилку?** [Створіть issue](https://github.com/sventmueller/dango/issues/new) і вкажіть, з яким агентом і в якому типі проєкту вона трапилася.

## Можливості коротко

- **Усі агенти в одній хронології.** Claude через власну команду `claude`, Codex, Antigravity і OpenCode через Agent Client Protocol, інші з реєстру ACP, а також агент, вбудований у програму, для Anthropic, OpenAI, Google Gemini, OpenRouter, Ollama і LM Studio. Відповіді, виклики інструментів, запити дозволів, плани, списки справ, субагенти й фонові задачі мають однаковий вигляд, хоч який агент працює.
- **Переглянути й відкотити.** Перед кожним запитом Dango зберігає контрольну точку. Те, що змінив агент, можна переглянути й відкотити для кожного повідомлення окремо, а чат може працювати у власному git worktree і передавати свою роботу через злиття або cherry-pick.
- **Одне вікно на папку.** Файли, термінали, сторінки браузера, ШІ-чати, diff і попередні перегляди є вкладками macOS у цьому вікні. На бічній панелі розміщено Файли, Пошук, Агенти, Git, Тести, Налагодження, CI і Контейнери.
- **Справжній редактор коду.** Підсвічування синтаксису, кілька курсорів, згортання, `.editorconfig`, мовні сервери для 17 мов з автодоповненням, переходом до визначення, посиланнями, перейменуванням, швидкими виправленнями та ієрархіями, а також передбачення під час редагування від GitHub Copilot або локальної моделі.
- **Вбудовані налагоджувач, Git і CI.** Точки зупину й покрокове виконання для Rust, C, C++, Swift, Go, JavaScript, TypeScript і Python; індексування окремих фрагментів, гілки, stash, конфлікти й граф комітів; запуски, завдання й журнали з GitHub Actions і GitLab CI.
- **Обережно з вашими папками.** Папка, якій ви не довіряєте, нічого не запускає: ні процесів git, ні мовних серверів, ні хуків, ні агентів. Деструктивні команди git ніколи не дозволяються назавжди, а коміти перевіряються на секрети.
- **Диктування.** Говоріть у редактор і в поле повідомлення, онлайн через OpenAI чи Groq або локально з Whisper і Parakeet.
- **Нативний до кісток.** Вікна, вкладки, меню й панелі інструментів AppKit, TextKit 2 для редактора, Metal для термінала, WebKit лише у вкладці браузера. Темний режим, «Збільшити контраст» і VoiceOver працюють, як у будь-якій програмі для Mac.
- **Вашою мовою.** Інтерфейс доступний 35 мовами: англійською, арабською, вʼєтнамською, гінді, голландською, грецькою, данською, івритом, індонезійською, іспанською, італійською, каталанською, китайською (спрощеною), китайською (традиційною), корейською, малайською, німецькою, норвезькою, польською, португальською (Бразилія), португальською (Португалія), російською, румунською, словацькою, словенською, тайською, турецькою, угорською, українською, фінською, французькою, хорватською, чеською, шведською та японською.

## Вимоги

- macOS 14 Sonoma або новіша, на Apple Silicon або Intel. Dango розробляється й тестується на macOS 27.
- Для ШІ-чатів: агент, яким ви хочете користуватися; див. [ШІ-агенти](#ші-агенти).
- Для мовних серверів і адаптерів налагодження, які Dango встановлює на ваш запит: Go для gopls і `dlv`; Node.js для серверів TypeScript, Python, JSON, YAML, CSS, HTML і shell та налагоджувача JavaScript; Xcode Command Line Tools для clangd, sourcekit-lsp і `lldb-dap`. rust-analyzer завантажується з його випусків на GitHub.
- Для передбачень під час редагування: підписка GitHub Copilot (підійде й безкоштовна) або модель fill-in-the-middle в Ollama чи LM Studio.

## Встановлення

**З образу диска.** Кожен випуск є образом диска `Dango-<version>.dmg` з однією універсальною програмою для Apple Silicon та Intel, підписаною Developer ID і нотаризованою Apple. Відкрийте його й перетягніть Dango до папки «Програми». Homebrew Cask встановлює той самий образ. Жодного випуску ще не опубліковано.

**Оновлення.** Dango з образу диска сам оновлюється через [Sparkle](https://sparkle-project.org). Під час другого запуску він питає, чи можна самостійно перевіряти оновлення; доки ви не погодитеся, він не надсилає жодного запиту. **Dango › Перевірити наявність оновлень…** перевіряє одразу. Оновлення підписано власним ключем програми, який Sparkle перевіряє, перш ніж щось установити. Власноруч зібрана версія не оновлюється сама.

**З вихідного коду.** Див. [Збирання з вихідного коду](#збирання-з-вихідного-коду), а потім перемістіть `target/release/Dango.app` до `/Applications`.

**Команда для термінала.** **Dango › Інсталювати команду «dango»…** записує невеликий скрипт у `~/.local/bin/dango` без прав адміністратора; `~/.local/bin` має бути у вашому `PATH`. Тоді `dango .` відкриває поточну папку, а `dango file.rs` відкриває файл. Dango ніколи не замінює там файл, який записав не він сам.

## Початок роботи

1. **Відкрийте папку** за допомогою ⌘O або `dango <folder>`. Першого разу Dango запитає, чи довіряєте ви їй (див. [Довіра](#довіра)).
2. **Бічна панель** перемикається між розділами Файли (⌘1), Пошук (⌘2), Агенти (⌘3), Git (⌘4), Тести (⌘5), Налагодження (⌘6), CI (⌘7) і Контейнери (⌘8); клацання правою кнопкою ховає ті, якими ви не користуєтеся, а ⌃⌘S згортає бічну панель.
3. **Кожен документ є вкладкою** вікна папки, власною вкладкою macOS. «+» в кінці панелі вкладок і ⌘T пропонують новий файл, термінал, браузер і кожного встановленого агента, також у власному git worktree; якщо втримувати «+», те саме зʼявиться як меню.
4. **Швидко відкрити** (⌘P) знаходить файли, а з `#` знаходить символи проєкту; ⇧⌘F шукає й замінює в проєкті.
5. **Говоріть з агентом** у вкладці ШІ. ⌘Esc переводить фокус клавіатури в його поле повідомлення й назад.
6. **Параметри** (⌘,) містять вкладки Загальні, CI, Агенти, Власний агент, Мовний сервер, Диктування і Передбачення.

На панелі інструментів розміщено кнопки «назад» і «вперед» місцями, які ви редагували (⌃- і ⌃⇧-), гілку, «Швидко відкрити» та огляд «Активність», що показує все, що працює. **Відкрити поруч** у контекстному меню файлу показує другий документ поруч із першим. Після перезапуску чи збою кожне вікно повертається зі своїми вкладками, а редактори з незбереженим текстом повертаються разом із цим текстом. Зображення, аудіо, відео, шрифти й документи Office відкриваються у вкладці через Quick Look, PDF через PDFKit.

## ШІ-агенти

| Агент | Як працює | Що потрібно |
|---|---|---|
| Claude | команда `claude`, з якою Dango спілкується напряму через її протокол stream-json | встановлений `claude` з виконаним входом; Dango шукає в `PATH` оболонки входу, у `~/.local/bin`, `~/.claude/local`, `/opt/homebrew/bin` і `/usr/local/bin`. Вхід виконується лише в самому `claude` |
| Codex | `codex-acp` через Agent Client Protocol (ACP) | Node.js і npm; Dango встановлює пакет закріпленої версії на ваш запит |
| Antigravity | `agy acp` | ваш власний `agy` у `PATH` або завантаження закріпленої версії, що встановлюється на ваш запит |
| OpenCode | `opencode acp` | ваш власний `opencode` у `PATH` або завантаження закріпленої версії, що встановлюється на ваш запит |
| Інші ACP-агенти | з реєстру ACP, який завантажується лише на ваш запит | те, що вказано в записі реєстру; записи без контрольної суми встановлюються лише після вашого підтвердження |
| Власний агент | вбудований у програму, з інструментами для файлів, пошуку, команд, діагностики й вебзапитів | ключ API для Anthropic, OpenAI, Google Gemini або OpenRouter, що зберігається у вʼязці; Ollama або LM Studio на цьому Mac без ключа; будь-який сервер, що підтримує API OpenAI або Anthropic |

**Параметри › Агенти** показує, які агенти є на цьому Mac, встановлює інші та їхні оновлення й відкриває реєстр ACP. Агентів, яких встановлює Dango, закріплено за перевіреними версіями й звірено з їхніми опублікованими контрольними сумами (npm integrity або SHA-256); Dango не запускає пакетів `npx` без версії.

### Хронологія

Кожен агент працює у вкладці ШІ з однаковою хронологією: відповіді, виклики інструментів з їхнім виводом, запити дозволів, запитання, плани для схвалення й коментування (⌥⌘K), списки справ, субагенти й фонові задачі. Дві кнопки в заголовку вкладки показують запущені субагенти й фонові процеси. Згадайте файл, `@terminal` або `@browser`, щоб передати агентові їхній вміст. Зелена крапка на вкладці позначає сеанс, що працює, червона позначає сеанс, що чекає на вас, а сповіщення повідомляє, коли сеанс завершився чи чекає, поки ви дивитеся деінде. Для Claude рядок стану показує контекст і використання.

### Дозволи й режими

Нові чати починаються в режимі «Вручну»: агент питає, перш ніж змінювати файли чи виконувати команди. Для деструктивних команд git (`push --force`, `reset --hard`, `clean -fd`) Dango не пропонує «Завжди дозволяти». Власний агент зберігає свої правила «Завжди дозволяти» для кожного проєкту, показує їх у **Параметри › Власний агент** і щоразу питає про деструктивні команди git, хоч би що було збережено; Claude та ACP-агенти зберігають такі правила у власній конфігурації. З режимом «Дозволити все» і без пісочниці чат показує постійне попередження.

### Контрольні точки та worktree

Перед кожним запитом Dango зберігає контрольну точку як коміт у `refs/ide-checkpoints/` у репозиторії проєкту або у власній папці для проєкту без git; звичайні push чи fetch ніколи їх не переносять. Те, що змінив агент, можна переглянути й відкотити для кожного повідомлення окремо. Чат може працювати у власному git worktree: панель Git показує, що він змінив, і переносить роботу через злиття або cherry-pick.

## Редактор

- **Підсвічування синтаксису, номери рядків і позначки змін** відносно останнього коміту, пошук і заміна, Швидко відкрити (⌘P) і пошук у проєкті (⇧⌘F).
- **Відступи** відповідають файлу та `.editorconfig`: табуляція чи пробіли, автоматичні відступи, парні дужки.
- **Кілька курсорів:** ⌥-клацання, ⌥-перетягування для стовпця, ⌃⇧↑ і ⌃⇧↓, ⌘D для наступного входження.
- **Згортання** (⌥⌘← і ⌥⌘→, з ⇧ для всього), перемикання коментарів (⌘/), перехід до рядка (⌃G), видимі пробіли й перенесення рядків (⌥Z).
- **Файли зберігають кодування**, мітку порядку байтів і закінчення рядків. Файл, змінений на диску, перезавантажується, якщо в редакторі немає незбереженого тексту; інакше панель пропонує відмінності та злиття.
- **Передбачення під час редагування.** Поки ви друкуєте, сірим зʼявляється пропозиція, і Tab приймає її. Вона надходить від GitHub Copilot або від локальної моделі в Ollama чи LM Studio, як вибрано в **Параметри › Передбачення**; локальна модель залишає ваш код на цьому Mac.
- **Мінікарта й закріплене прокручування** (меню «Редактор»): вузьке зображення всього файлу поруч із текстом і рядки заголовків блоків, у яких лежить верхній рядок, закріплені над ним.
- **Діагностика в кінці рядка** (меню «Перегляд»): найсерйозніше повідомлення кожного рядка після секунди спокою, зі значком рівня серйозності.
- **Живий попередній перегляд статичних сторінок:** Редактор › Відкрити у вкладці браузера роздає сторінки папки, якій ви довіряєте, просто з Dango і перезавантажує вкладку, коли файл зберігається.
- **Prettier** форматує JavaScript, TypeScript, CSS, HTML, Markdown та інше там, де проєкт його налаштовує, власним `node_modules/.bin/prettier` проєкту; параметр `formatter` вибирає форматувальник для кожної мови.
- **Режим Vim** (Редактор › Режим Vim): нормальний режим, режими вставлення, вибору й заміни, лічильники, оператори з рухами й текстовими обʼєктами, `.`, регістри, мітки й макроси. `u` і ⌃R використовують відміну дій редактора, а один прохід вставлення — це один крок. `"+` і `"*` — це буфер обміну; параметр `vimClipboard` робить буфером обміну й безіменний регістр. `/`, `?`, `n`, `N`, `*`, `:s` і `:%s` шукають за регулярними виразами Rust, а не за шаблонами Vim: немає `\v`, а замість `\<` і `\>` — `\b`. Команди Ex: `:w`, `:q`, `:wq`, `:x`, `:noh` і `:<line>`. У нормальному режимі Vim забирає ⌃G у переходу до рядка.
- **Синхронізація параметрів** через папку в iCloud Drive (**Параметри › Загальні**): ваші параметри й скорочення йдуть за вами на інші ваші Mac; шляхи, локальні адреси й згоди залишаються на кожному з них свої.

## Мовні сервери

Go, Rust, TypeScript і JavaScript, Python, C, C++ і Objective-C, Swift, shell-скрипти, JSON, YAML, CSS, HTML, TOML, Markdown і Lua, а також ваші власні сервери з **Параметри › Мовний сервер**. Dango встановлює сервер на ваш запит у власну папку інструментів і використовує власний `tsc` проєкту TypeScript, якщо він може працювати як мовний сервер.

Що вони дають: діагностика (⌘' і ⇧⌘' переходять між повідомленнями), підказки при наведенні (⌃⌘I), автодоповнення (⌥Esc), довідка щодо сигнатур, перехід до визначення (⌃⌘J), визначення типу й реалізації, посилання (⌃⇧⌘F), ієрархії викликів і типів (⌃⇧⌘H), перейменування (⌃⌘E), форматування (⌥⇧F), семантичні кольори, згортання та структура (⇧⌘O); типи й назви параметрів усередині рядка; швидкі виправлення й рефакторинги за лампочкою (⌥⌘A); символи проєкту через ⌥⌘O.

Поряд із власним сервером файлу ESLint перевіряє JavaScript і TypeScript проєктів, які його використовують, зі своїми швидкими виправленнями, а скорочення Emmet зʼявляються в автодоповненні для HTML, CSS і JSX. Dango встановлює обидва на ваш запит; **Параметри › Загальні** за бажанням виправляє проблеми ESLint під час збереження.

## Тести

Панель «Тести» показує тести папки за пакетами й файлами разом з їхнім станом: `cargo test` або cargo-nextest, Go, pytest, Vitest і Jest. Символ біля кожного тесту на полях запускає його, ⌥-клацання запускає його налагодження, а невдалий assert позначає свій рядок. Меню «Налагодження» запускає тест у позиції курсора (⌃⌥⌘U), останні тести повторно (⌃⌥⌘G) або всі, а також налагоджує тест у позиції курсора. Тести виконуються лише в довірених папках, бо вони запускають код проєкту; `cargo test` виводить список своїх тестів, лише коли ви попросите, бо складання списку збирає кожну тестову програму.

## Налагоджувач

Точки зупину, зокрема з умовами та як точки журналювання, покрокове виконання, потоки з їхніми стеками викликів, змінні й контрольні вирази в Інспекторі (⌥⌘I), значення поруч із кодом, поки програму призупинено, і консоль налагодження, що обчислює вирази в призупиненому кадрі.

| Мова | Адаптер налагодження |
|---|---|
| Rust, C, C++, Swift | `lldb-dap` з Xcode Command Line Tools |
| Go | `dlv` |
| JavaScript, TypeScript | налагоджувач JavaScript на Node.js |
| Python | debugpy |

Файл `.vscode/launch.json` проєкту зчитується. Меню «Налагодження» використовує скорочення Xcode: ⌘\\ ставить точку зупину, ⌘Y вмикає чи вимикає всі точки, ⌃⌘Y продовжує виконання, F6, F7 і F8 виконують крок з обходом, із заходом і з виходом, ⌘. зупиняє.

## Термінал

Термінали у вкладках (⌃\`) із середовищем оболонки входу, відмальовані за допомогою Metal. ⌘K очищує екран. Вставлене чи перетягнуте зображення передається агентові програмування, що працює в терміналі, або вставляється шлях до збереженої копії. ⌘-клацання відкриває посилання й імена файлів. Сервер розробки, запущений терміналом, можна відкрити у вкладці браузера.

## Браузер

Вкладка браузера з полем адреси (⌘L), кнопками «назад» і «вперед» (⌘[ і ⌘]), оновленням (⌘R), пошуком, завантаженнями з попереднім запитанням і Веб-інспектором. `@browser` передає сторінку агентові з позначкою тексту ззовні.

## Git

Панель Git індексує й відкидає зміни у файлах чи окремих фрагментах, створює коміти, комітить і виконує push або синхронізацію, перемикає й створює гілки, зберігає stash, розвʼязує конфлікти злиття й малює граф останніх комітів. Blame показує, хто востаннє змінив рядок під курсором, або стовпець для всього файлу. Кнопка пише повідомлення коміту за допомогою ШІ; diff надсилається лише після того, як gitleaks не знайшов у ньому секретів, і кожен коміт так само перевіряється на секрети.

## CI

GitHub Actions і GitLab CI, також GitHub Enterprise Server і GitLab на власному сервері:

- запуски, завдання й журнали поточної гілки;
- повторний запуск невдалих завдань, окремого завдання або, на GitHub, усього запуску; запуск ручних завдань або схвалення розгортань, що очікують; запуск нового pipeline чи workflow, який можна запустити вручну; скасування;
- відкриті pull request або merge request та issues, які відкриваються у вкладці браузера;
- журнал невдалого завдання, переданий агентові з позначкою тексту ззовні.

Токен береться з вʼязки, з `gh` чи `glab`, із середовища оболонки входу або з того, що ви вводите в **Параметри › CI**.

## Контейнери

Панель «Контейнери» показує проєкти Compose у Docker з їхніми сервісами, окремі контейнери, образи й томи та стежить за подіями Docker, щойно вони стаються. Файл Compose із папки зʼявляється як проєкт ще до того, як існує бодай один із його контейнерів. Контейнери запускаються, зупиняються й перезапускаються; їхні журнали та оболонка відкриваються у вкладках термінала, а опублікований порт — у вкладці браузера. Видалення контейнера, образу чи тому й очищення невикористовуваних даних спершу запитують підтвердження. Команди up, down і pull із Compose виконуються лише в довірених папках, бо Compose збирає й запускає те, що описує проєкт. Меню панелі вибирає контекст Docker для вікна, не змінюючи той, яким користуються ваші оболонки; ті самі команди є в меню «Контейнери». Панелі потрібен командний рядок `docker`, Docker 24.0.6 або новіший.

## Markdown

- **Попередній перегляд.** Файл Markdown відкривається з попереднім переглядом поруч; **Перегляд › Показати/сховати попередній перегляд поруч** (⇧⌘V) закриває й відкриває його, а **Параметри › Загальні** вимикає автоматичний попередній перегляд. Попередній перегляд малює формули, діаграми Mermaid, Graphviz і PlantUML та зображення з папки; зображення з інтернету завантажуються лише в папці, якій ви довіряєте, або після того, як ви попросите про це в попередньому перегляді.
- **Меню «Формат»:** жирний (⌘B), курсив (⌘I), закреслений (⇧⌘X), код (⌥⇧⌘C), посилання (⇧⌘K), заголовки 1–3 (⌥⌘1–⌥⌘3), марковані й нумеровані списки, задачі, цитати й блоки коду. Кожна команда вмикає або вимикає формат для виділення чи рядків і відміняється одним кроком.
- **Вставлення.** Текст із Word чи вебсторінки надходить як Markdown, а його зображення як файли поруч із документом; ⌥⇧⌘V вставляє простий текст.
- **Експорт.** **Файл › Експортувати** записує PDF, один файл HTML із вбудованими зображеннями або документ Word. Зображення з інтернету додаються лише з папки, якій ви довіряєте.
- **Відкрити в Splat.** Якщо встановлено [Splat](https://github.com/sventmueller/splat), **Файл › Відкрити в Splat** і контекстні меню дерева файлів та вкладок відкривають у ньому документ, попередньо зберігши його.

## Диктування

Диктуйте в поле повідомлення вкладки ШІ або в редактор: кнопкою мікрофона там, через **Редагування › Почати диктування** (⌃⌥D) або клавішею fn (утримуйте, щоб записувати, торкніться двічі, щоб запис тривав далі). Розпізнавання мовлення те саме, що в [Lowspeak](https://github.com/sventmueller/lowspeak); сам Lowspeak встановлювати не потрібно.

- **Параметри › Диктування** задає режим і модель (онлайн з OpenAI чи Groq, локально з Whisper чи Parakeet), мову, постобробку, мікрофон і ваш власний словник.
- **Локальні моделі** завантажуються з Hugging Face, коли ви вибираєте одну з них, з показом поступу й можливістю скасувати. Вони потрапляють до папок, якими користується Lowspeak, тож кожна з двох програм використовує те, що завантажила інша. Локальна модель залишає запис на цьому Mac.
- **Онлайн-транскрипція** потребує ключа OpenAI або Groq, який Dango зберігає у власному записі вʼязки.
- **З Lowspeak.** Якщо Lowspeak налаштовано не за замовчуванням, вкладка «Диктування» один раз пропонує перенести його параметри, а на запит і його ключі; macOS питає, перш ніж Dango прочитає ключ (виберіть «Дозволити», а не «Завжди дозволяти»).
- **Дозволи.** macOS запитує доступ до мікрофона під час першого диктування. Клавіша fn працює, поки Dango є активною програмою, а Lowspeak не запущено; для неї потрібен дозвіл «Доступність», який Dango запитує після першого диктування, ніколи не під час запуску.

## Довіра

Папка може змусити програми запускатися, щойно в ній щось запущено: хуки git і параметри репозиторію, як-от `core.fsmonitor`, мовні сервери з `node_modules`, хуки агентів, `.mcp.json`. Коли ви вперше відкриваєте папку, Dango запитує, чи довіряєте ви їй.

- **Довірена:** git, мовні сервери, налагоджувачі, агенти й CI працюють для цієї папки й усього, що в ній.
- **Обмежена:** ви можете читати й редагувати; позначки змін у редакторі беруться з прямого читання `.git`. Ніщо з того, що налаштовує папка, не запускається. Панелі Git, CI і ШІ повідомляють про це й пропонують довіритися папці.

Текст, що походить не від вас, може містити інструкції, призначені для керування агентом (prompt injection). Тому вивід термінала (`@terminal`), сторінка браузера (`@browser`), журнал CI, переданий агентові, файл поза проєктом і довший текст, вставлений із вебсторінки, передаються з позначкою: на мітці написано «Зовнішній вміст», а агент отримує текст із приміткою, що це ненадійні дані, інструкцій у яких він не повинен виконувати. Вебсторінки власного агента надходять із тією самою приміткою. Вставлений текст вважається текстом із вебсторінки, коли браузер вказує це в буфері обміну, як роблять Safari, Chrome і Firefox; текст з інших місць, а також коротка фраза з кількох слів, залишаються вашими.

## Пісочниця

Сам Dango працює без App Sandbox, бо її успадкувала б кожна програма, яку він запускає: термінали, git, мовні сервери й агенти не могли б працювати. Натомість кожен ШІ-чат має перемикач пісочниці, типово вимкнений. Що він обмежує, залежить від агента, і про це каже підказка перемикача:

| Агент | З увімкненою пісочницею |
|---|---|
| Claude | команди оболонки виконуються у власній пісочниці Claude; його інструменти для файлів і вебу ні |
| Codex | команди та зміни записують лише в проєкт, без мережі |
| Власний агент | файли, вебзапити й команди лишаються в межах проєкту та дозволених папок, без мережі (`sandbox-exec`) |
| Antigravity, OpenCode | немає пісочниці, яку Dango міг би ввімкнути |

## Вигляд і доступність

- **Темний режим** відповідає системі; **Збільшити контраст** і **Зменшити рух** враховуються.
- **VoiceOver** називає бічну панель, вкладки, картки хронології ШІ, рядки Git і CI, налагоджувач і текст термінала. Точки зупину ніколи не розрізняються лише кольором.
- **Клавіатура.** Кожна команда має скорочення, і всі їх можна змінити в `keybindings.json`; ⌥⌘\` переходить до наступної панелі.
- **Справа наліво.** В арабській та івриті вікно віддзеркалюється, а подання коду залишаються зліва направо.

Що Dango додає до AppKit, за розділами, описано в [ACCESSIBILITY.md](../../../ACCESSIBILITY.md).

## Конфіденційність і безпека

- **Жодної телеметрії,** аналітики чи звітів про збої, що кудись надсилаються. Помилки потрапляють до системного журналу (Console.app, під назвою програми).
- **Мережа лише для того, що запускаєте ви:** агенти, якими ви користуєтеся, кожен зі своїм сервісом; реєстр ACP і завантаження агентів, мовних серверів, адаптерів налагодження й моделей диктування, коли ви їх запитуєте; хости CI, у які ви входите; передбачення від Copilot, якщо ви його вибрали; провайдери власного агента; онлайн-транскрипція, якщо ви її вибрали; сторінки, які ви відкриваєте у вкладці браузера; і перевірка оновлень, щойно ви її дозволили.
- **Код залишає Mac** лише там, де ви вибрали для цього сервіс: агент, передбачення Copilot, повідомлення коміту, написане ШІ. Diff для повідомлення коміту надсилається лише після того, як gitleaks не знайшов у ньому секретів.
- **Ключі й токени** залишаються у вʼязці macOS, ніколи не у файлі параметрів. Ключі інших програм, як-от Lowspeak, читаються лише за вашої згоди й лише один раз.
- **Закріплені завантаження.** Агентів, мовні сервери й адаптери налагодження, які встановлює Dango, закріплено за перевіреними версіями й звірено з їхніми контрольними сумами.
- **Підписування коду** з Hardened Runtime; оновлення встановлюються лише з власним підписом програми.

## Де зберігаються дані

`<id>` є ідентифікатором пакета: `local.agentide` для випуску (`local.agentide.debug` для налагоджувальних збірок). Він не містить відображуваної назви, тож після перейменування всі дані зберігаються.

| Місце | Що |
|---|---|
| `~/Library/Application Support/<id>/` | `settings.json`, `state.json`, `keybindings.json`, `trust.json`; `threads/` (список панелі ШІ), `agent-threads/` (діалоги власного агента), `layouts/` (вкладки для кожного проєкту), `recovery/` (незбережені редактори після збою), `checkpoints/` (для папок без git), `worktrees/`, `agents/` і `tools/` (встановлені агенти, мовні сервери й адаптери налагодження), `task-output/` |
| `~/Library/Caches/<id>/` | вставлені зображення, скрипти інтеграції з оболонкою, реєстр ACP; можна видалити |
| `~/Library/Logs/<id>/dictation/` | файли журналу диктування |
| `~/Library/Application Support/Lowspeak` і `FluidAudio` | локальні моделі диктування, спільні з Lowspeak |
| `~/Library/WebKit/<id>/` | файли cookie й дані вебсайтів вкладки браузера |
| `<project>/.dango/settings.json` | власні параметри проєкту |
| git-репозиторій проєкту | контрольні точки як коміти в `refs/ide-checkpoints/`; звичайні push чи fetch ніколи їх не переносять |
| вʼязка, служба `<id>` | ключі API власного агента й диктування, токени CI |
| `~/.local/bin/dango` | команда для термінала, якщо ви її встановили |

Claude зберігає власні сеанси в `~/.claude/projects`; Dango читає їх, щоб відновити сеанс, але не змінює їх.

## Відомі обмеження

- **Без App Sandbox** для самої програми, бо її успадкували б термінали, git, мовні сервери й агенти; папці потрібно довіряти, перш ніж запуститься будь-що, що вона налаштовує. Antigravity і OpenCode не мають пісочниці, яку Dango міг би ввімкнути.
- **Показники використання й розподіл контексту Claude** спираються на частини його протоколу, позначені як експериментальні, і приховуються, якщо їх немає.
- **Відкат діалогу** працює лише для Claude; для інших агентів відкочується лише код.
- **Вхід до CI через браузер** вимкнено; використовуйте `gh`, `glab`, токен або середовище.
- **Gemini CLI не пропонується:** Google припинив вхід з особистим обліковим записом і радить Antigravity. Попередні чати Gemini лишаються доступними для читання.

## Збирання з вихідного коду

Вам потрібні:

- macOS 14 або новіша з Xcode Command Line Tools (`xcode-select --install`); сам Xcode не потрібен.
- Rust у версії, яку вказує `rust-toolchain.toml`. `rust` з Homebrew збирає для процесора цього Mac; універсальна збірка випуску потребує rustup з цілями `aarch64-apple-darwin` і `x86_64-apple-darwin`.
- Копії [splat](https://github.com/sventmueller/splat) і [lowspeak](https://github.com/sventmueller/lowspeak) поруч із цією (`../splat`, `../lowspeak`), обидві на гілці `main`; робочий простір бере з них crates за шляхом.
- cmake для кожної збірки з диктуванням (`make run`, `make build`, `make release`), яка збирає whisper.cpp. `make check` збирає без нього.

| Команда | Що робить |
|---|---|
| `make run` | збирає налагоджувальну програму (`target/debug/Dango Debug.app`) і відкриває її |
| `make build` | збирає програму для випуску (`target/release/Dango.app`), підписану локальним сертифікатом, який перша збірка створює у вʼязці входу; збільшує номер збірки у `VERSION` |
| `make lint` | форматування й clippy; попередження спричиняють збій |
| `make check` | `lint`, потім усі тести; не потребує вʼязки, вікна чи мережі |
| `make test` | `check`, потім самотест `probe` і аудит доступності, зліва направо й справа наліво, у справжній програмі |
| `make perf` | часові бюджети у збірці для випуску; має сенс лише на Mac, який більше нічим не зайнятий |
| `make release` | пробний запуск випуску в `target/release-dry-run/`, підписаний локальним сертифікатом; нічого нікуди не надсилає |
| `make release-notarized` | `check`, потім сам випуск у `dist/`: підпис Developer ID, нотаризація, канал оновлень, підписаний власним ключем програми; збільшує номер збірки |

Налагоджувальна версія й версія для випуску є окремими програмами з власними параметрами й даними. Збирання, тестування, самотести, випуск і правила, яких дотримується код, описано в [docs/development.md](../../../docs/development.md), рішення, що стоять за ними, описано в [docs/plan.md](../../../docs/plan.md). Примітки до випуску містить [RELEASE_NOTES.md](../../../RELEASE_NOTES.md), перекладені поруч із кожним README в `assets/readme/<language>/`.
