# Dango

**코딩 에이전트와 함께 작업하기 위한 네이티브 macOS 편집기.**

Dango는 코드와 그 코드를 변경하는 에이전트, 그리고 그 주변의 모든 것을 폴더마다 하나의 윈도우에 모읍니다. 언어 서버와 편집 예측을 갖춘 편집기, 터미널, 브라우저, Git, CI, 디버거, 그리고 Claude, Codex, Antigravity, OpenCode 또는 앱에 내장된 에이전트와의 AI 스레드가 그 안에 있습니다. 모든 에이전트는 같은 타임라인에서 작업하고, 파일을 변경하거나 명령을 실행하기 전에 묻고, 각 프롬프트 전에 체크포인트를 남깁니다. 따라서 에이전트가 한 일을 메시지별로 검토하고 되감을 수 있습니다. 폴더가 구성한 것은 그 폴더를 신뢰하기 전에는 아무것도 실행되지 않으며, 외부에서 온 텍스트는 신뢰할 수 없음으로 표시되어 에이전트에 전달됩니다. 편집기와 메시지 필드에 받아쓰기할 수 있으며, 음성 인식을 Mac 안에서만 처리할 수도 있습니다. Dango는 Electron 없이 진짜 AppKit 컨트롤 위에서 Rust로 작성되었고, 35개 언어를 지원하며, 원격 측정이 없습니다.

## 기능 한눈에 보기

- **모든 에이전트를 하나의 타임라인에서.** Claude는 자체 `claude` 명령으로, Codex, Antigravity, OpenCode는 Agent Client Protocol로 동작하며, ACP 레지스트리에서 더 많은 에이전트를 추가할 수 있습니다. 여기에 Anthropic, OpenAI, Google Gemini, OpenRouter, Ollama, LM Studio를 지원하는 앱 내장 에이전트도 있습니다. 응답, 도구 호출, 권한 요청, 계획, 할 일, 하위 에이전트, 백그라운드 작업은 어떤 에이전트가 실행되든 똑같이 보입니다.
- **검토하고 되감기.** Dango는 각 프롬프트 전에 체크포인트를 저장합니다. 에이전트가 변경한 내용은 메시지별로 검토하고 되감을 수 있으며, 스레드는 별도의 Git 워크트리에서 작업하고 그 결과를 병합이나 체리픽으로 넘겨줄 수 있습니다.
- **폴더마다 하나의 윈도우.** 파일, 터미널, 브라우저 페이지, AI 스레드, 차이점, 미리보기는 그 윈도우의 macOS 탭입니다. 사이드바에는 파일, 검색, 에이전트, Git, 테스트, 디버그, CI, 컨테이너가 있습니다.
- **진짜 코드 편집기.** 구문 색상, 여러 커서, 접기, `.editorconfig`, 자동 완성·정의로 이동·참조·이름 변경·빠른 수정·계층 구조를 지원하는 17개 언어의 언어 서버, 그리고 GitHub Copilot 또는 로컬 모델의 편집 예측.
- **디버거, Git, CI 내장.** Rust, C, C++, Swift, Go, JavaScript, TypeScript, Python의 중단점과 단계별 실행. 개별 헝크 스테이징, 브랜치, 스태시, 충돌, 커밋 그래프. GitHub Actions와 GitLab CI의 실행, 잡, 로그.
- **폴더를 신중하게 다룹니다.** 신뢰하지 않은 폴더에서는 아무것도 시작되지 않습니다. Git 프로세스도, 언어 서버도, 훅도, 에이전트도 마찬가지입니다. 파괴적인 Git 명령은 절대 영구적으로 허용되지 않으며, 커밋에 시크릿이 있는지 검사합니다.
- **받아쓰기.** 편집기와 메시지 필드에 말로 입력할 수 있습니다. OpenAI나 Groq를 통해 온라인으로, 또는 Whisper와 Parakeet로 로컬에서 인식합니다.
- **뼛속까지 네이티브.** AppKit 윈도우, 탭, 메뉴, 도구 막대. 편집기에는 TextKit 2, 터미널에는 Metal을 사용하고, WebKit은 브라우저 탭에서만 사용합니다. 다크 모드, 대비 증가, VoiceOver는 다른 모든 Mac 앱에서처럼 작동합니다.
- **사용자의 언어로.** 인터페이스는 35개 언어로 제공됩니다. 아랍어, 카탈루냐어, 중국어(간체), 중국어(번체), 크로아티아어, 체코어, 덴마크어, 네덜란드어, 영어, 핀란드어, 프랑스어, 독일어, 그리스어, 히브리어, 힌디어, 헝가리어, 인도네시아어, 이탈리아어, 일본어, 한국어, 말레이어, 노르웨이어, 폴란드어, 포르투갈어(브라질), 포르투갈어(포르투갈), 루마니아어, 러시아어, 슬로바키아어, 슬로베니아어, 스페인어, 스웨덴어, 태국어, 튀르키예어, 우크라이나어, 베트남어.

## 요구 사항

- Apple Silicon 또는 Intel 기반 Mac의 macOS 14 Sonoma 이상. Dango는 macOS 27에서 개발 및 테스트됩니다.
- AI 스레드에는 사용하려는 에이전트가 필요합니다. [AI 에이전트](#ai-에이전트)를 참고하십시오.
- 언어 서버와 디버그 어댑터는 요청하면 Dango가 설치하며, 다음이 필요합니다. gopls와 `dlv`에는 Go, TypeScript, Python, JSON, YAML, CSS, HTML, 셸 서버와 JavaScript 디버거에는 Node.js, clangd, sourcekit-lsp, `lldb-dap`에는 Xcode Command Line Tools. rust-analyzer는 GitHub 릴리스에서 다운로드됩니다.
- 편집 예측에는 GitHub Copilot 플랜(무료 플랜도 됩니다) 또는 Ollama나 LM Studio의 fill-in-the-middle 모델이 필요합니다.

## 설치

**디스크 이미지에서.** 각 릴리스는 디스크 이미지 `Dango-<version>.dmg`이며, Apple Silicon과 Intel을 위한 유니버설 앱 하나가 들어 있고, Developer ID로 서명되어 Apple의 공증을 받았습니다. 이미지를 열고 Dango를 응용 프로그램 폴더로 드래그하십시오. Homebrew Cask로도 같은 이미지를 설치할 수 있습니다. 아직 공개된 릴리스는 없습니다.

**업데이트.** 디스크 이미지로 설치한 Dango는 [Sparkle](https://sparkle-project.org)로 스스로 최신 상태를 유지합니다. 두 번째 실행 시 스스로 업데이트를 확인해도 되는지 묻고, 동의하기 전에는 어떤 요청도 보내지 않습니다. **Dango › 업데이트 확인…** 메뉴 항목은 즉시 확인합니다. 업데이트는 앱 고유의 키로 서명되며, Sparkle은 무엇이든 설치하기 전에 이를 검사합니다. 직접 빌드한 Dango에는 업데이터가 없습니다.

**소스에서.** [소스에서 빌드하기](#소스에서-빌드하기)를 참고한 다음, `target/release/Dango.app`을 `/Applications`로 옮기십시오.

**터미널 명령.** **Dango › ‘dango’ 명령 설치…** 메뉴 항목은 관리자 권한 없이 `~/.local/bin/dango`에 작은 스크립트를 씁니다. `~/.local/bin`이 `PATH`에 있어야 합니다. 그러면 `dango .`는 현재 폴더를, `dango file.rs`는 파일을 엽니다. Dango는 자신이 직접 쓰지 않은 파일을 그곳에서 덮어쓰지 않습니다.

## 시작하기

1. ⌘O 또는 `dango <folder>`로 **폴더를 엽니다**. 처음에는 Dango가 그 폴더를 신뢰하는지 묻습니다([신뢰](#신뢰) 참고).
2. **사이드바**는 파일(⌘1), 검색(⌘2), 에이전트(⌘3), Git(⌘4), 테스트(⌘5), 디버그(⌘6), CI(⌘7), 컨테이너(⌘8) 사이를 전환합니다. 사용하지 않는 항목은 오른쪽 클릭으로 가릴 수 있으며, ⌃⌘S는 사이드바를 접습니다.
3. **모든 문서는 폴더 윈도우의 탭**이며, macOS 자체의 탭입니다. 탭 막대 끝의 ‘+’와 ⌘T는 새로운 파일, 터미널, 브라우저, 설치된 각 에이전트를 제공하며, 별도의 Git 워크트리에서도 열 수 있습니다. ‘+’를 길게 누르면 같은 항목이 메뉴로 표시됩니다.
4. ⌘P로 **빠르게 열기**를 사용하면 파일을, `#`을 붙이면 프로젝트의 심볼을 찾습니다. ⇧⌘F는 프로젝트에서 검색하고 대치합니다.
5. AI 탭에서 **에이전트와 대화합니다**. ⌘Esc는 키보드 포커스를 메시지 필드로 옮기고, 다시 누르면 원래 위치로 돌아갑니다.
6. ⌘,로 여는 **설정**에는 일반, CI, 에이전트, 내장 에이전트, 언어 서버, 받아쓰기, 예측 탭이 있습니다.

도구 막대에는 편집한 위치를 오가는 뒤로 및 앞으로(⌃- 및 ⌃⇧-), 브랜치, 빠르게 열기, 그리고 실행 중인 모든 항목을 나열하는 활동 개요가 있습니다. 파일의 컨텍스트 메뉴에서 **옆에 열기**를 선택하면 두 번째 문서를 첫 번째 문서 옆에 표시합니다. 재시동하거나 충돌한 후에도 모든 윈도우가 탭과 함께 돌아오며, 저장하지 않은 텍스트가 있는 편집기는 그 텍스트와 함께 돌아옵니다. 이미지, 오디오, 비디오, 서체, Office 문서는 훑어보기를 통해, PDF는 PDFKit을 통해 탭에서 열립니다.

## AI 에이전트

| 에이전트 | 실행 방식 | 필요한 것 |
|---|---|---|
| Claude | `claude` 명령, stream-json 프로토콜로 직접 통신 | `claude`가 설치되어 있고 로그인되어 있어야 합니다. Dango는 로그인 셸의 `PATH`, `~/.local/bin`, `~/.claude/local`, `/opt/homebrew/bin`, `/usr/local/bin`에서 찾습니다. 로그인은 `claude` 자체에서만 이루어집니다 |
| Codex | Agent Client Protocol(ACP)을 통한 `codex-acp` | Node.js와 npm. 요청하면 Dango가 고정된 버전의 패키지를 설치합니다 |
| Antigravity | `agy acp` | `PATH`에 있는 직접 설치한 `agy`, 또는 요청 시 설치되는 고정된 버전의 다운로드 |
| OpenCode | `opencode acp` | `PATH`에 있는 직접 설치한 `opencode`, 또는 요청 시 설치되는 고정된 버전의 다운로드 |
| 기타 ACP 에이전트 | ACP 레지스트리에서. 레지스트리는 요청할 때만 가져옵니다 | 레지스트리 항목에 명시된 것. 체크섬이 없는 항목은 확인한 후에만 설치됩니다 |
| 내장 에이전트 | 앱에 내장. 파일, 검색, 명령, 진단, 웹 요청을 위한 도구 포함 | Anthropic, OpenAI, Google Gemini 또는 OpenRouter의 API 키(키체인에 보관). 이 Mac의 Ollama나 LM Studio는 키 없이 사용. OpenAI나 Anthropic의 API를 지원하는 모든 서버 |

**설정 › 에이전트**는 이 Mac에 있는 에이전트를 보여 주고, 다른 에이전트와 그 업데이트를 설치하며, ACP 레지스트리를 엽니다. Dango가 설치하는 에이전트는 테스트된 버전으로 고정되며 공개된 체크섬(npm integrity 또는 SHA-256)으로 검증됩니다. Dango는 버전이 지정되지 않은 `npx` 패키지를 실행하지 않습니다.

### 타임라인

모든 에이전트는 같은 타임라인을 가진 AI 탭에서 작업합니다. 응답, 출력이 포함된 도구 호출, 권한 요청, 질문, 승인하고 의견을 남길 수 있는 계획(⌥⌘K), 할 일, 하위 에이전트, 백그라운드 작업이 표시됩니다. 탭 헤더의 두 버튼은 실행 중인 하위 에이전트와 백그라운드 프로세스를 나열합니다. 파일, `@terminal` 또는 `@browser`를 멘션하면 그 내용을 에이전트에 넘겨줍니다. 탭의 초록색 점은 작업 중인 세션을, 빨간색 점은 응답을 기다리는 세션을 나타내며, 다른 곳을 보고 있는 동안 세션이 끝나거나 대기하면 알림으로 알려 줍니다. Claude의 경우 상태 줄에 컨텍스트와 사용량이 표시됩니다.

### 권한과 모드

새 스레드는 ‘수동’ 모드로 시작합니다. 에이전트는 파일을 변경하거나 명령을 실행하기 전에 묻습니다. 파괴적인 Git 명령(`push --force`, `reset --hard`, `clean -fd`)에 대해서는 Dango가 ‘항상 허용’을 제공하지 않습니다. 내장 에이전트는 ‘항상 허용’ 규칙을 프로젝트별로 보관하고 **설정 › 내장 에이전트**에 나열하며, 파괴적인 Git 명령에 대해서는 무엇이 저장되어 있든 매번 묻습니다. Claude와 ACP 에이전트는 이러한 규칙을 각자의 구성에 보관합니다. ‘모두 허용’이면서 샌드박스가 없으면 스레드에 경고가 계속 표시됩니다.

### 체크포인트와 워크트리

Dango는 각 프롬프트 전에 체크포인트를 저장합니다. 체크포인트는 프로젝트 저장소의 `refs/ide-checkpoints/` 아래에 커밋으로, Git이 없는 프로젝트에서는 별도의 폴더에 저장되며, 일반적인 푸시나 페치로는 절대 전송되지 않습니다. 에이전트가 변경한 내용은 메시지별로 검토하고 되감을 수 있습니다. 스레드는 별도의 Git 워크트리에서 작업할 수 있습니다. Git 패널은 스레드가 변경한 내용을 보여 주고, 병합이나 체리픽으로 작업을 가져옵니다.

## 편집기

- 마지막 커밋 대비 **구문 색상, 행 번호, 변경 표시**, 찾기 및 대치, 빠르게 열기(⌘P), 프로젝트 검색(⇧⌘F).
- **들여쓰기**는 파일과 `.editorconfig`를 따릅니다. 탭 또는 공백, 자동 들여쓰기, 괄호 쌍.
- **여러 커서:** ⌥-클릭, ⌥-드래그로 열 선택, ⌃⇧↑ 및 ⌃⇧↓, ⌘D로 다음 항목.
- **접기**(⌥⌘← 및 ⌥⌘→, ⇧를 함께 누르면 전체), 주석 전환(⌘/), 행으로 이동(⌃G), 공백 문자 표시와 줄 바꿈(⌥Z).
- **파일은 인코딩**, 바이트 순서 표시, 줄 끝 문자를 유지합니다. 디스크에서 변경된 파일은 편집기에 저장하지 않은 텍스트가 없으면 다시 로드됩니다. 그렇지 않으면 막대에 차이점과 병합이 제공됩니다.
- **편집 예측.** 입력하는 동안 제안이 회색으로 나타나며, Tab 키로 수락합니다. 제안은 **설정 › 예측**에서 선택한 대로 GitHub Copilot 또는 Ollama나 LM Studio의 로컬 모델에서 제공됩니다. 로컬 모델을 사용하면 코드가 이 Mac에 머무릅니다.
- **미니맵과 고정 스크롤**(편집기 메뉴): 미니맵은 텍스트 옆에 파일 전체를 좁게 축소해 보여 주고, 고정 스크롤은 맨 위 행이 속한 블록의 머리글 행을 그 위에 고정합니다.
- **줄 끝에 진단 표시**(보기 메뉴): 1초 동안 입력이 없으면 각 행에서 가장 심각한 메시지를 심각도를 나타내는 기호와 함께 줄 끝에 표시합니다.
- **정적 페이지 실시간 미리보기:** 편집기 › 브라우저 탭에서 열기는 신뢰하는 폴더의 페이지를 Dango가 직접 제공하고, 파일이 저장되면 탭을 다시 로드합니다.
- **Prettier**는 프로젝트에서 설정한 경우 JavaScript, TypeScript, CSS, HTML, Markdown 등을 프로젝트 자체의 `node_modules/.bin/prettier`로 포맷합니다. `formatter` 설정으로 언어별 포맷터를 선택합니다.
- **Vim 모드**(편집기 › Vim 모드): Normal, Insert, Visual, Replace 모드, 횟수, 이동 명령 및 텍스트 객체와 결합하는 연산자, `.`, 레지스터, 마크, 매크로. `u`와 ⌃R은 편집기의 실행 취소를 사용하며, 한 번의 입력은 실행 취소 한 단계입니다. `"+`와 `"*`는 클립보드이며, `vimClipboard` 설정을 켜면 이름 없는 레지스터도 클립보드가 됩니다. `/`, `?`, `n`, `N`, `*`, `:s`, `:%s`는 Vim의 패턴이 아닌 Rust의 정규 표현식으로 검색합니다. `\v`는 없으며, `\<`와 `\>` 대신 `\b`를 사용합니다. Ex 명령은 `:w`, `:q`, `:wq`, `:x`, `:noh`, `:<line>`입니다. Normal 모드에서는 ⌃G가 ‘행으로 이동’ 대신 Vim으로 전달됩니다.
- **설정 동기화**(**설정 › 일반**): iCloud Drive의 폴더를 통해 설정과 단축키가 다른 Mac으로 따라갑니다. 경로, 로컬 주소, 동의는 각 Mac에 그대로 남습니다.

## 언어 서버

Go, Rust, TypeScript 및 JavaScript, Python, C, C++ 및 Objective-C, Swift, 셸 스크립트, JSON, YAML, CSS, HTML, TOML, Markdown, Lua, 그리고 **설정 › 언어 서버**에서 추가한 사용자 서버. Dango는 요청하면 서버를 자체 도구 폴더에 설치하며, TypeScript 프로젝트 자체의 `tsc`가 언어 서버 역할을 할 수 있으면 그것을 사용합니다.

제공하는 기능: 진단(⌘' 및 ⇧⌘'로 이동), 호버(⌃⌘I), 자동 완성(⌥Esc), 시그니처 도움말, 정의로 이동(⌃⌘J), 유형 정의 및 구현, 참조(⌃⇧⌘F), 호출 계층 및 유형 계층(⌃⇧⌘H), 이름 변경(⌃⌘E), 포맷(⌥⇧F), 시맨틱 색상, 접기, 개요(⇧⌘O). 행 안에 표시되는 유형과 매개변수 이름. 전구 아이콘 뒤의 빠른 수정 및 리팩토링(⌥⌘A). ⌥⌘O로 찾는 프로젝트 심볼.

파일 자체의 서버 외에도, ESLint를 사용하는 프로젝트에서는 ESLint가 JavaScript와 TypeScript를 검사하고 빠른 수정을 제공하며, HTML, CSS, JSX의 자동 완성에는 Emmet 약어가 나타납니다. Dango는 요청하면 둘 다 설치합니다. 원하는 경우 **설정 › 일반**에서 저장할 때 ESLint 문제를 수정하도록 할 수 있습니다.

## 테스트

테스트 패널은 폴더의 테스트를 패키지와 파일별로 상태와 함께 나열합니다. 지원 도구는 `cargo test` 또는 cargo-nextest, Go, pytest, Vitest, Jest입니다. 행 번호 옆 여백에서 각 테스트 옆의 기호를 누르면 테스트를 실행하고, ⌥-클릭하면 디버그하며, 실패한 assert는 해당 행에 표시됩니다. 디버그 메뉴는 커서 위치의 테스트를 실행하거나(⌃⌥⌘U), 마지막 테스트를 다시 실행하거나(⌃⌥⌘G), 모든 테스트를 실행하고, 커서 위치의 테스트를 디버그합니다. 테스트는 프로젝트의 코드를 실행하므로 신뢰하는 폴더에서만 실행됩니다. 나열하면 모든 테스트 프로그램이 빌드되므로 `cargo test`는 요청할 때만 테스트를 나열합니다.

## 디버거

| Rust, C, C++, Swift | Xcode Command Line Tools의 `lldb-dap` |
| Go | `dlv` |
| JavaScript, TypeScript | Node.js에서 실행되는 JavaScript 디버거 |
| Python | debugpy |

프로젝트의 `.vscode/launch.json`을 읽습니다. 디버그 메뉴는 Xcode의 단축키를 사용합니다. ⌘\\는 중단점을 설정하고, ⌘Y는 모든 중단점을 켜거나 끄고, ⌃⌘Y는 계속하며, F6, F7, F8은 스텝 오버, 스텝 인, 스텝 아웃하고, ⌘.는 중단합니다.

## Git

Git 패널은 파일이나 개별 헝크를 스테이징하고 폐기하며, 커밋하고, 커밋 후 푸시하거나 동기화하고, 브랜치를 전환하고 생성하며, 스태시를 보관하고, 병합 충돌을 해결하고, 최근 커밋의 그래프를 그립니다. Blame은 커서가 있는 행을 마지막으로 변경한 사람을 보여 주거나, 파일 전체에 대해 열로 보여 줍니다. 버튼 하나로 AI가 커밋 메시지를 작성합니다. 차이점은 gitleaks가 그 안에서 시크릿을 찾지 못한 후에만 전송되며, 모든 커밋도 시크릿이 있는지 검사합니다.

## CI

GitHub Actions와 GitLab CI, 그리고 GitHub Enterprise Server와 자체 관리형 GitLab도 지원합니다.

- 현재 브랜치의 실행, 잡, 로그.
- 실패한 잡, 단일 잡 또는 GitHub에서는 전체 실행의 재실행. 수동 잡 시작이나 대기 중인 배포 승인. 새 파이프라인이나 수동으로 시작할 수 있는 워크플로 시작. 취소.
- 열려 있는 풀 리퀘스트 또는 병합 요청과 이슈. 브라우저 탭에서 열립니다.
- 실패한 잡의 로그를 외부 텍스트로 표시하여 에이전트에 넘겨주기.

토큰은 키체인, `gh` 또는 `glab`, 로그인 셸의 환경에서 가져오거나, **설정 › CI**에서 입력한 것을 사용합니다.

## 컨테이너

컨테이너 패널은 Docker의 Compose 프로젝트와 그 서비스, 단독 컨테이너, 이미지, 볼륨을 표시하고, Docker의 이벤트를 발생하는 즉시 반영합니다. 폴더의 Compose 파일은 컨테이너가 아직 하나도 없어도 프로젝트로 표시됩니다. 컨테이너는 시작, 중단, 재시작할 수 있으며, 로그와 셸은 터미널 탭에서 열리고, 공개된 포트는 브라우저 탭에서 열립니다. 컨테이너, 이미지, 볼륨을 삭제하거나 사용하지 않는 데이터를 정리하기 전에는 먼저 확인을 요청합니다. Compose는 프로젝트에 기술된 내용을 빌드하고 실행하므로 Compose의 up, down, pull은 신뢰하는 폴더에서만 실행됩니다. 패널의 메뉴는 셸이 사용하는 컨텍스트를 바꾸지 않고 윈도우의 Docker 컨텍스트를 선택합니다. 같은 명령은 컨테이너 메뉴에도 있습니다. `docker` 명령어 라인과 Docker 24.0.6 이상이 필요합니다.

## Markdown

- **미리보기.** Markdown 파일은 옆에 미리보기를 표시한 상태로 열립니다. **보기 › 옆에 미리보기 보기/가리기**(⇧⌘V)로 미리보기를 닫거나 열 수 있으며, **설정 › 일반**에서 자동 미리보기를 끌 수 있습니다. 미리보기는 수식, Mermaid, Graphviz, PlantUML 다이어그램과 폴더의 이미지를 그립니다. 웹의 이미지는 신뢰하는 폴더에서이거나 미리보기에서 요청한 후에만 로드됩니다.
- **포맷 메뉴:** 굵게(⌘B), 기울임꼴(⌘I), 취소선(⇧⌘X), 코드(⌥⇧⌘C), 링크(⇧⌘K), 제목 1–3(⌥⌘1–⌥⌘3), 글머리 기호 목록과 번호 목록, 작업, 인용, 코드 블록. 각 명령은 선택 영역이나 행에 대해 켜고 끄며, 한 번에 실행 취소할 수 있습니다.
- **붙여넣기.** Word나 웹 페이지의 텍스트는 Markdown으로, 그 이미지는 문서 옆의 파일로 들어옵니다. ⌥⇧⌘V는 일반 텍스트로 붙여넣습니다.
- **내보내기.** **파일 › 내보내기**는 PDF, 이미지가 포함된 단일 HTML 파일 또는 Word 문서로 씁니다. 웹의 이미지는 신뢰하는 폴더에서만 함께 포함됩니다.
- **Splat에서 열기.** [Splat](https://github.com/sventmueller/splat)이 설치되어 있으면 **파일 › Splat에서 열기**와 파일 트리 및 탭의 컨텍스트 메뉴가 문서를 저장한 후 Splat에서 엽니다.

## 받아쓰기

AI 탭의 메시지 필드나 편집기에 받아쓰기할 수 있습니다. 그곳의 마이크 버튼, **편집 › 받아쓰기 시작**(⌃⌥D) 또는 fn 키(길게 눌러 녹음, 두 번 탭하여 계속 녹음)를 사용합니다. 음성 인식은 [Lowspeak](https://github.com/sventmueller/lowspeak)의 것이지만, Lowspeak 자체를 설치할 필요는 없습니다.

- **설정 › 받아쓰기**에서 모드와 모델(OpenAI나 Groq로 온라인, Whisper나 Parakeet로 로컬), 언어, 후처리, 마이크, 사용자 어휘를 설정합니다.
- **로컬 모델**은 선택하면 Hugging Face에서 다운로드되며, 진행 상황이 표시되고 취소할 수도 있습니다. 모델은 Lowspeak가 사용하는 폴더에 저장되므로, 두 앱은 서로가 다운로드한 모델을 사용할 수 있습니다. 로컬 모델을 사용하면 녹음이 이 Mac에 머무릅니다.
- **온라인 전사**에는 OpenAI 또는 Groq 키가 필요하며, Dango는 이 키를 자체 키체인 항목에 보관합니다.
- **Lowspeak에서.** Lowspeak가 기본값과 다르게 설정되어 있으면, 받아쓰기 탭은 그 설정을 가져오도록 한 번 제안하고, 요청하면 키도 가져옵니다. Dango가 키를 읽기 전에 macOS가 묻습니다(‘항상 허용’이 아니라 ‘허용’을 선택하십시오).
- **권한.** 처음 받아쓰기할 때 macOS가 마이크 접근을 묻습니다. fn 키는 Dango가 활성 앱이고 Lowspeak가 실행 중이 아닐 때 작동합니다. fn 키에는 손쉬운 사용 권한이 필요하며, Dango는 이를 첫 받아쓰기 후에 요청하고 실행 시에는 절대 요청하지 않습니다.

## 신뢰

폴더는 그 안에서 무언가가 시작되자마자 프로그램을 실행시킬 수 있습니다. Git 훅과 `core.fsmonitor` 같은 저장소 설정, `node_modules`의 언어 서버, 에이전트 훅, `.mcp.json`이 그렇습니다. 폴더를 처음 열 때 Dango는 그 폴더를 신뢰하는지 묻습니다.

- **신뢰함:** Git, 언어 서버, 디버거, 에이전트, CI가 이 폴더와 그 아래의 모든 항목에 대해 실행됩니다.
- **제한됨:** 읽고 편집할 수 있습니다. 편집기의 변경 표시는 `.git`을 직접 읽어서 표시합니다. 폴더가 구성한 것은 아무것도 시작되지 않습니다. Git, CI, AI 패널은 이를 알리고 폴더를 신뢰하도록 제안합니다.

사용자에게서 오지 않은 텍스트에는 에이전트를 조종하려는 지시가 담겨 있을 수 있습니다(프롬프트 인젝션). 따라서 터미널의 출력(`@terminal`), 브라우저 페이지(`@browser`), 에이전트에 넘긴 CI 로그, 프로젝트 밖의 파일, 웹 페이지에서 붙여넣은 긴 텍스트는 표시가 붙은 채로 전달됩니다. 칩에는 ‘외부 콘텐츠’라고 표시되며, 에이전트는 이 텍스트가 신뢰할 수 없는 데이터이고 그 안의 지시를 따라서는 안 된다는 안내와 함께 텍스트를 받습니다. 내장 에이전트가 가져온 웹 페이지에도 같은 안내가 붙습니다. 붙여넣은 텍스트는 Safari, Chrome, Firefox처럼 브라우저가 클립보드에 그렇게 표시한 경우 웹 페이지에서 온 것으로 간주됩니다. 다른 곳에서 온 텍스트와 몇 단어로 된 짧은 구절은 사용자 자신의 것으로 남습니다.

## 샌드박스

Dango 자체는 App Sandbox 없이 실행됩니다. Dango가 시작하는 모든 프로그램이 이를 상속하게 되어, 터미널, Git, 언어 서버, 에이전트가 작동할 수 없기 때문입니다. 대신 각 AI 스레드에는 샌드박스 스위치가 있으며, 기본적으로 꺼져 있습니다. 무엇을 제한하는지는 에이전트에 따라 다르며, 스위치의 도움말 태그에 그 내용이 표시됩니다.

| 에이전트 | 샌드박스를 켰을 때 |
|---|---|
| Claude | 셸 명령은 Claude 자체의 샌드박스에서 실행됩니다. 파일 도구와 웹 도구는 그렇지 않습니다 |
| Codex | 명령과 변경은 프로젝트 안에서만 쓰며, 네트워크는 사용할 수 없습니다 |
| 내장 에이전트 | 파일, 웹 요청, 명령이 프로젝트와 허용된 폴더 안에 머무르며, 네트워크는 사용할 수 없습니다(`sandbox-exec`) |
| Antigravity, OpenCode | Dango가 켤 수 있는 샌드박스가 없습니다 |

## 모양과 손쉬운 사용

- **다크 모드**는 시스템을 따릅니다. **대비 증가**와 **동작 줄이기**도 반영됩니다.
- **VoiceOver**는 사이드바, 탭, AI 타임라인의 카드, Git 및 CI 행, 디버거, 터미널의 텍스트에 이름을 붙여 읽습니다. 중단점은 절대 색상만으로 구분되지 않습니다.
- **키보드.** 모든 명령에 단축키가 있으며, 모두 `keybindings.json`에서 변경할 수 있습니다. ⌥⌘\`는 다음 패널로 이동합니다.
- **오른쪽에서 왼쪽으로.** 아랍어와 히브리어에서는 윈도우가 좌우 반전되며, 코드 보기는 왼쪽에서 오른쪽으로 유지됩니다.

Dango가 AppKit 위에 더한 것은 영역별로 [ACCESSIBILITY.md](../../../ACCESSIBILITY.md)에 정리되어 있습니다.

## 언어

인터페이스는 35개 언어로 번역되어 있습니다. 아랍어, 카탈루냐어, 중국어(간체), 중국어(번체), 크로아티아어, 체코어, 덴마크어, 네덜란드어, 영어, 핀란드어, 프랑스어, 독일어, 그리스어, 히브리어, 힌디어, 헝가리어, 인도네시아어, 이탈리아어, 일본어, 한국어, 말레이어, 노르웨이어, 폴란드어, 포르투갈어(브라질), 포르투갈어(포르투갈), 루마니아어, 러시아어, 슬로바키아어, 슬로베니아어, 스페인어, 스웨덴어, 태국어, 튀르키예어, 우크라이나어, 베트남어.

Dango는 **시스템 설정 › 일반 › 언어 및 지역**의 언어 순서를 따릅니다. 같은 곳의 **응용 프로그램**에서 Dango에만 적용할 언어를 따로 고를 수도 있습니다. 사용자의 언어로 된 번역이 없으면 영어를 사용합니다. 용어는 하나의 용어집인 [docs/glossary.md](../../../docs/glossary.md)와 Apple의 공식 번역을 따르므로, Dango는 Mac의 다른 부분과 같은 말로 표시됩니다.

## 개인정보 보호 및 보안

- **원격 측정 없음.** 분석도 없고, 어디로도 충돌 보고서를 보내지 않습니다. 오류는 시스템 로그(콘솔 앱, 앱 이름 아래)에 기록됩니다.
- **네트워크는 사용자가 시작한 작업에만 사용합니다.** 사용하는 에이전트(각각 자체 서비스와 통신), 요청할 때의 ACP 레지스트리와 에이전트, 언어 서버, 디버그 어댑터, 받아쓰기 모델의 다운로드, 로그인한 CI 호스트, 선택한 경우 Copilot의 편집 예측, 내장 에이전트의 제공자, 선택한 경우 온라인 전사, 브라우저 탭에서 여는 페이지, 그리고 허용한 후의 업데이트 확인.
- **코드가 Mac 밖으로 나가는 것은** 그 용도로 서비스를 선택한 경우뿐입니다. 에이전트, Copilot의 예측, AI가 작성하는 커밋 메시지가 그렇습니다. 커밋 메시지를 위한 차이점은 gitleaks가 그 안에서 시크릿을 찾지 못한 후에만 전송됩니다.
- **키와 토큰**은 설정 파일이 아니라 macOS 키체인에 보관됩니다. Lowspeak 등 다른 앱의 키는 동의한 경우에만, 그리고 한 번만 읽습니다.
- **고정된 다운로드.** Dango가 설치하는 에이전트, 언어 서버, 디버그 어댑터는 테스트된 버전으로 고정되며 체크섬으로 검증됩니다.
- **코드 서명**에는 Hardened Runtime을 사용합니다. 업데이트는 앱 고유의 서명이 있을 때만 설치됩니다.

## 데이터 저장 위치

`<id>`는 번들 식별자로, 릴리스 빌드에서는 `local.agentide`(디버그 빌드에서는 `local.agentide.debug`)입니다. 표시 이름을 포함하지 않으므로, 이름이 바뀌어도 모든 데이터가 유지됩니다.

| 위치 | 내용 |
|---|---|
| `~/Library/Application Support/<id>/` | `settings.json`, `state.json`, `keybindings.json`, `trust.json`; `threads/`(AI 패널의 목록), `agent-threads/`(내장 에이전트 대화), `layouts/`(프로젝트별 탭), `recovery/`(충돌 후 저장하지 않은 편집기), `checkpoints/`(Git이 없는 폴더용), `worktrees/`, `agents/` 및 `tools/`(설치된 에이전트, 언어 서버, 디버그 어댑터), `task-output/` |
| `~/Library/Caches/<id>/` | 붙여넣은 이미지, 셸 통합 스크립트, ACP 레지스트리. 삭제해도 됩니다 |
| `~/Library/Logs/<id>/dictation/` | 받아쓰기의 로그 파일 |
| `~/Library/Application Support/Lowspeak` 및 `FluidAudio` | 로컬 받아쓰기 모델. Lowspeak와 공유 |
| `~/Library/WebKit/<id>/` | 브라우저 탭의 쿠키와 웹 사이트 데이터 |
| `<project>/.dango/settings.json` | 프로젝트 자체의 설정 |
| 프로젝트의 Git 저장소 | `refs/ide-checkpoints/` 아래의 커밋으로 저장된 체크포인트. 일반적인 푸시나 페치로는 절대 전송되지 않습니다 |
| 키체인, 서비스 `<id>` | 내장 에이전트와 받아쓰기의 API 키, CI 토큰 |
| `~/.local/bin/dango` | 터미널 명령(설치한 경우) |

Claude는 자체 세션을 `~/.claude/projects` 아래에 보관합니다. Dango는 세션을 재개하기 위해 이를 읽지만, 변경하지는 않습니다.

## 알려진 제한 사항

- 앱 자체에는 **App Sandbox가 없습니다**. 터미널, Git, 언어 서버, 에이전트가 이를 상속하게 되기 때문입니다. 폴더가 구성한 것이 실행되려면 먼저 그 폴더를 신뢰해야 합니다. Antigravity와 OpenCode에는 Dango가 켤 수 있는 샌드박스가 없습니다.
- **Claude의 사용량 수치와 컨텍스트 세부 내역**은 실험적으로 표시된 프로토콜 일부에 의존하며, 해당 부분이 없으면 가려집니다.
- **대화 되감기**는 Claude에서만 작동합니다. 다른 에이전트에서는 코드만 되감깁니다.
- **브라우저를 통한 CI 로그인**은 꺼져 있습니다. `gh`, `glab`, 토큰 또는 환경 변수를 사용하십시오.
- **Gemini CLI는 제공되지 않습니다.** Google이 개인 계정 로그인을 종료하고 Antigravity로 안내하기 때문입니다. 이전 Gemini 스레드는 계속 읽을 수 있습니다.

## 소스에서 빌드하기

필요한 것:

- Xcode Command Line Tools(`xcode-select --install`)가 설치된 macOS 14 이상. Xcode 자체는 필요하지 않습니다.
- `rust-toolchain.toml`에 지정된 Rust. Homebrew의 `rust`는 이 Mac의 프로세서용으로 빌드합니다. 릴리스의 유니버설 빌드에는 대상 `aarch64-apple-darwin` 및 `x86_64-apple-darwin`이 추가된 rustup이 필요합니다.
- 이 저장소 옆(`../splat`, `../lowspeak`)에 있는 [splat](https://github.com/sventmueller/splat)과 [lowspeak](https://github.com/sventmueller/lowspeak)의 체크아웃. 둘 다 `main` 브랜치여야 합니다. 작업 공간은 이들로부터 크레이트를 경로로 가져옵니다.
- 받아쓰기가 포함된 모든 빌드(`make run`, `make build`, `make release`)에는 whisper.cpp를 빌드하기 위한 cmake. `make check`는 cmake 없이 빌드합니다.

| 명령 | 하는 일 |
|---|---|
| `make run` | 디버그 앱(`target/debug/Dango Debug.app`)을 빌드하고 엽니다 |
| `make build` | 릴리스 앱(`target/release/Dango.app`)을 빌드합니다. 첫 빌드가 로그인 키체인에 만드는 로컬 인증서로 서명하며, `VERSION`은 변경하지 않습니다 |
| `make lint` | 포맷과 clippy. 경고가 있으면 실패합니다 |
| `make check` | `lint` 후 모든 테스트. 키체인, 윈도우, 네트워크가 필요하지 않습니다 |
| `make test` | `check` 후 실제 앱에서 자체 테스트 `probe`와 손쉬운 사용 감사를 왼쪽에서 오른쪽, 오른쪽에서 왼쪽으로 실행합니다 |
| `make perf` | 릴리스 빌드에서의 시간 예산. 다른 작업이 없는 Mac에서만 의미가 있습니다 |
| `make release` | `target/release-dry-run/`으로의 릴리스 시험 실행. 로컬 인증서로 서명하며, 아무 데도 아무것도 보내지 않습니다 |
| `make release-notarized` | `check` 후 `dist/`로의 실제 릴리스. Developer ID 서명, 공증, 앱 고유의 키로 서명된 업데이트 피드. `VERSION`은 변경하지 않습니다 |
| `make deploy` | 변경 사항이 없고 녹색 CI 봉인이 있는 `main`에서 다음 버전을 공증하고 `VERSION`을 업데이트하여 커밋합니다. 릴리스 파일을 업로드하고 코드, CI 봉인 및 버전 태그를 푸시하면 GitHub가 릴리스를 자동으로 게시합니다 |

디버그 앱과 릴리스 앱은 각자의 설정과 데이터를 가진 별개의 앱입니다. 빌드, 테스트, 자체 테스트, 릴리스, 코드가 따르는 규칙은 [docs/development.md](../../../docs/development.md)에, 그 바탕이 되는 결정은 [docs/plan.md](../../../docs/plan.md)에 설명되어 있습니다. 릴리스 노트는 [RELEASE_NOTES.md](../../../RELEASE_NOTES.md)이며, 각 README 옆의 `assets/readme/<language>/`에 번역되어 있습니다.
