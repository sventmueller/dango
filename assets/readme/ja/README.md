# Dango

**コーディングエージェントと一緒に作業するための、ネイティブなmacOSエディタ。**

Dangoは、コードと、それを変更するエージェントと、その周りにあるすべてを、フォルダごとに1つのウインドウにまとめます。言語サーバと編集の予測を備えたエディタ、ターミナル、ブラウザ、Git、CI、デバッガ、そしてClaude、Codex、Antigravity、OpenCode、またはアプリに内蔵されたエージェントとのAIスレッドです。どのエージェントも同じタイムラインで作業し、ファイルを変更したりコマンドを実行したりする前に確認を求め、各プロンプトの前にチェックポイントを残します。そのため、エージェントが行ったことをメッセージごとに確認して巻き戻せます。フォルダで設定されたものは、そのフォルダを信頼するまで何も実行されず、外部からのテキストは、信頼されていないものとして印を付けてエージェントに渡されます。エディタとメッセージフィールドには音声入力ができ、音声認識をMac上だけで行うこともできます。DangoはElectronを使わず、本物のAppKitコントロール上にRustで書かれており、35の言語に対応し、テレメトリはありません。

## 主な機能

- **すべてのエージェントを1つのタイムラインで。** Claudeは専用の`claude`コマンドで、Codex、Antigravity、OpenCodeはAgent Client Protocolで動作し、ACPレジストリからほかのエージェントも追加できます。さらに、Anthropic、OpenAI、Google Gemini、OpenRouter、Ollama、LM Studioに対応した、アプリ内蔵のエージェントもあります。応答、ツール呼び出し、権限の要求、プラン、To-do、サブエージェント、バックグラウンドタスクは、どのエージェントが動いていても同じように表示されます。
- **確認して巻き戻す。** Dangoは各プロンプトの前にチェックポイントを残します。エージェントが変更した内容はメッセージごとに確認して巻き戻せます。スレッドは専用のGitワークツリーで作業し、その成果をマージまたはチェリーピックで引き渡すこともできます。
- **フォルダごとに1つのウインドウ。** ファイル、ターミナル、ブラウザのページ、AIスレッド、差分、プレビューは、そのウインドウのmacOSタブになります。サイドバーには“ファイル”、“検索”、“エージェント”、“Git”、“テスト”、“デバッグ”、“CI”、“コンテナ”があります。
- **本格的なコードエディタ。** シンタックスカラー、複数のキャレット、折りたたみ、`.editorconfig`、補完・定義へ移動・参照・名前の変更・クイックフィックス・階層表示に対応した17言語の言語サーバ、そしてGitHub Copilotまたはローカルモデルによる編集の予測。
- **デバッガ、Git、CIを内蔵。** Rust、C、C++、Swift、Go、JavaScript、TypeScript、Pythonのブレークポイントとステップ実行。個別のハンクのステージ、ブランチ、スタッシュ、競合、コミットグラフ。GitHub ActionsとGitLab CIの実行、ジョブ、ログ。
- **Tapaのターミナル。** 出力をコピー、保存、エージェントに渡せるコマンドブロック、履歴とプロジェクトからの提案が出る入力フィールド、履歴全体の検索、ターミナル内のプログラムからの通知と進行状況。
- **フォルダを慎重に扱います。** 信頼していないフォルダでは何も起動しません。Gitのプロセスも、言語サーバも、フックも、エージェントもです。破壊的なGitコマンドが恒久的に許可されることはなく、コミットはシークレットが含まれていないか検査されます。
- **音声入力。** エディタとメッセージフィールドに話しかけて入力できます。OpenAIまたはGroqでオンラインで、あるいはWhisperとParakeetでローカルで認識します。
- **骨の髄までネイティブ。** AppKitのウインドウ、タブ、メニュー、ツールバー。エディタにはTextKit 2、ターミナルにはMetalを使い、WebKitはブラウザタブでのみ使います。ダークモード、“コントラストを上げる”、VoiceOverは、ほかのMacアプリと同じように動作します。
- **お使いの言語で。** インターフェイスは35言語で用意されています。アラビア語、カタロニア語、中国語（簡体字）、中国語（繁体字）、クロアチア語、チェコ語、デンマーク語、オランダ語、英語、フィンランド語、フランス語、ドイツ語、ギリシャ語、ヘブライ語、ヒンディー語、ハンガリー語、インドネシア語、イタリア語、日本語、韓国語、マレー語、ノルウェー語、ポーランド語、ポルトガル語（ブラジル）、ポルトガル語（ポルトガル）、ルーマニア語、ロシア語、スロバキア語、スロベニア語、スペイン語、スウェーデン語、タイ語、トルコ語、ウクライナ語、ベトナム語。

## 動作環境

- Apple SiliconまたはIntelのMacで、macOS 14 Sonoma以降。DangoはmacOS 27で開発・テストされています。
- AIスレッドには、使いたいエージェント。[AIエージェント](#aiエージェント)を参照してください。
- 言語サーバとデバッグアダプタ（求めに応じてDangoがインストールします）には、次のものが必要です。goplsと`dlv`にはGo、TypeScript、Python、JSON、YAML、CSS、HTML、シェルの各サーバとJavaScriptデバッガにはNode.js、clangd、sourcekit-lsp、`lldb-dap`にはXcode Command Line Tools。rust-analyzerはGitHubのリリースからダウンロードされます。
- 編集の予測には、GitHub Copilotのプラン（無料プランで十分です）、またはOllamaかLM Studioのfill-in-the-middleモデル。

## インストール

**ディスクイメージから。** 各リリースはディスクイメージ`Dango-<version>.dmg`で、Apple SiliconとIntelの両方に対応したユニバーサルアプリが1つ入っており、Developer IDで署名され、Appleによって公証されています。開いて、Dangoを“アプリケーション”フォルダにドラッグしてください。Homebrew Caskでも同じイメージをインストールできます。リリースはまだ公開されていません。

**アップデート。** ディスクイメージからインストールしたDangoは、[Sparkle](https://sparkle-project.org)で自動的に最新の状態を保ちます。2回目の起動時に、自分でアップデートを確認してよいかを尋ねます。同意するまでは、一切リクエストを送信しません。**Dango › アップデートを確認…** を選ぶと、すぐに確認します。アップデートはアプリ独自の鍵で署名されており、Sparkleは何かをインストールする前にその署名を検証します。自分でビルドしたDangoには、アップデート機能がありません。

**ソースから。** [ソースからのビルド](#ソースからのビルド)を参照し、`target/release/Dango.app`を`/Applications`に移動してください。

**ターミナルコマンド。** **Dango › “dango”コマンドをインストール…** を選ぶと、管理者権限なしで`~/.local/bin/dango`に小さなスクリプトが書き込まれます。`~/.local/bin`が`PATH`に含まれている必要があります。その後は、`dango .`で現在のフォルダが、`dango file.rs`でファイルが開きます。Dangoは、自分で書き込んだものではないファイルをそこで置き換えることはありません。

## はじめに

1. **フォルダを開く**には、⌘Oまたは`dango <folder>`を使います。初回は、そのフォルダを信頼するかどうかをDangoが尋ねます（[信頼](#信頼)を参照）。
2. **サイドバー**では、“ファイル”（⌘1）、“検索”（⌘2）、“エージェント”（⌘3）、“Git”（⌘4）、“テスト”（⌘5）、“デバッグ”（⌘6）、“CI”（⌘7）、“コンテナ”（⌘8）を切り替えます。使わないものは右クリックで非表示にでき、⌃⌘Sでサイドバーを折りたたみます。
3. **どの書類もタブ**として、フォルダのウインドウに開きます。macOS自体のタブです。タブバーの末尾にある“+”と⌘Tで、新規ファイル、ターミナル、ブラウザ、インストール済みの各エージェントを開けます。エージェントは専用のGitワークツリーでも開けます。“+”を長押しすると、同じものがメニューとして表示されます。
4. **クイックオープン**（⌘P）でファイルを、`#`を付けるとプロジェクトのシンボルを探せます。⇧⌘Fでプロジェクト内を検索・置換します。
5. **エージェントと話す**には、AIタブを使います。⌘Escで、キーボードフォーカスがそのメッセージフィールドに移り、もう一度押すと元に戻ります。
6. **設定**（⌘,）には、“一般”、“ターミナル”、“CI”、“エージェント”、“Software Factory”、“内蔵エージェント”、“言語サーバ”、“音声入力”、“予測”のタブがあります。

ツールバーには、編集した場所をたどる戻る/進む（⌃-と⌃⇧-）、ブランチ、“クイックオープン”、そして実行中のすべてを一覧表示する“アクティビティ”の概要があります。ファイルのコンテキストメニューの**横に開く**で、2つ目の書類を1つ目の横に表示します。再起動やクラッシュのあとも、各ウインドウはタブとともに戻り、未保存のテキストがあるエディタはそのテキストごと戻ります。イメージ、オーディオ、ビデオ、フォント、Office書類はクイックルックで、PDFはPDFKitでタブに開きます。

## AIエージェント

| エージェント | 動作のしくみ | 必要なもの |
|---|---|---|
| Claude | `claude`コマンド。そのstream-jsonプロトコルで直接やり取りします | `claude`がインストールされ、サインイン済みであること。Dangoは、ログインシェルの`PATH`、`~/.local/bin`、`~/.claude/local`、`/opt/homebrew/bin`、`/usr/local/bin`を探します。サインインは`claude`自体の中でのみ行います |
| Codex | Agent Client Protocol（ACP）経由の`codex-acp` | Node.jsとnpm。求めに応じて、Dangoが固定バージョンのパッケージをインストールします |
| Antigravity | `agy acp` | `PATH`上にある手元の`agy`、または求めに応じてインストールされる固定バージョンのダウンロード |
| OpenCode | `opencode acp` | `PATH`上にある手元の`opencode`、または求めに応じてインストールされる固定バージョンのダウンロード |
| ほかのACPエージェント | ACPレジストリから。レジストリは求めたときにだけ取得されます | レジストリの項目に記載されているもの。チェックサムのない項目は、確認したあとにだけインストールされます |
| 内蔵エージェント | アプリに内蔵。ファイル、検索、コマンド、診断、Webリクエスト用のツールを備えています | Anthropic、OpenAI、Google Gemini、OpenRouterのAPIキー（キーチェーンに保管）。このMac上のOllamaまたはLM Studioならキーは不要。OpenAIまたはAnthropicのAPIに対応した任意のサーバも使えます |

**設定 › エージェント**には、このMacにあるエージェントが表示され、ほかのエージェントとそのアップデートをインストールでき、ACPレジストリを開けます。Dangoがインストールするエージェントはテスト済みのバージョンに固定され、公開されているチェックサム（npm integrityまたはSHA-256）で検証されます。Dangoは、バージョン指定のない`npx`パッケージを実行しません。

### タイムライン

どのエージェントも、同じタイムラインを持つAIタブで作業します。応答、出力付きのツール呼び出し、権限の要求、質問、承認やコメント（⌥⌘K）ができるプラン、To-do、サブエージェント、バックグラウンドタスクが並びます。タブのヘッダにある2つのボタンで、実行中のサブエージェントとバックグラウンドプロセスを一覧表示できます。ファイル、`@terminal`、`@browser`をメンションすると、その内容をエージェントに渡せます。タブの緑の点は作業中のセッションを、赤の点は応答を待っているセッションを示し、ほかの作業をしている間にセッションが終わったり待機したりすると通知でお知らせします。Claudeでは、ステータスラインにコンテキストと使用量が表示されます。

### 権限とモード

新しいスレッドは“手動”モードで始まります。エージェントは、ファイルを変更したりコマンドを実行したりする前に確認を求めます。破壊的なGitコマンド（`push --force`、`reset --hard`、`clean -fd`）については、Dangoは“常に許可”を提供しません。内蔵エージェントは“常に許可”のルールをプロジェクトごとに保存して**設定 › 内蔵エージェント**に一覧表示し、破壊的なGitコマンドについては、何が保存されていても毎回確認します。Claudeと各ACPエージェントは、そうしたルールをそれぞれの設定に保存します。“すべてを許可”でサンドボックスなしの場合、スレッドには常に警告が表示されます。

### チェックポイントとワークツリー

Dangoは各プロンプトの前にチェックポイントを残します。チェックポイントは、プロジェクトのリポジトリの`refs/ide-checkpoints/`以下にコミットとして、Gitのないプロジェクトでは専用のフォルダに保存されます。通常のプッシュやフェッチで送受信されることはありません。エージェントが変更した内容は、メッセージごとに確認して巻き戻せます。スレッドは専用のGitワークツリーで作業できます。Gitパネルにはその変更内容が表示され、マージまたはチェリーピックで作業を取り込みます。

## エディタ

- **シンタックスカラー、行番号、最後のコミットに対する変更マーク**、検索と置換、クイックオープン（⌘P）、プロジェクト検索（⇧⌘F）。
- **インデント**はファイルと`.editorconfig`に従います。タブまたはスペース、自動インデント、括弧のペア。
- **複数のキャレット:** ⌥クリック、⌥ドラッグで列、⌃⇧↑と⌃⇧↓、⌘Dで次の出現箇所。
- **折りたたみ**（⌥⌘←と⌥⌘→、⇧を付けるとすべて）、コメントの切り替え（⌘/）、行へ移動（⌃G）、空白文字の表示と行の折り返し（⌥Z）。
- **ファイルはエンコーディング**、バイトオーダーマーク、改行コードを保ちます。ディスク上で変更されたファイルは、エディタに未保存のテキストがなければ再読み込みされます。ある場合は、バーに差分とマージが表示されます。
- **編集の予測。** 入力中に提案がグレーで表示され、Tabキーで確定します。提案は、**設定 › 予測**での選択に応じて、GitHub CopilotまたはOllamaかLM Studioのローカルモデルから届きます。ローカルモデルなら、コードはこのMacから出ません。
- **ミニマップと固定スクロール**（“エディタ”メニュー）: ミニマップはテキストの横にファイル全体を細長く縮小して表示し、固定スクロールは先頭行が含まれるブロックの見出し行をその上に固定します。
- **行末に診断を表示**（“表示”メニュー）: 1秒間入力が止まると、各行で最も重大なメッセージを、重大度を示す記号とともに行末に表示します。
- **静的ページのライブプレビュー:** “エディタ › ブラウザタブで開く”を選ぶと、信頼済みのフォルダのページをDango自身が配信し、ファイルが保存されるたびにタブを再読み込みします。
- **Prettier**は、プロジェクトで設定されている場合、JavaScript、TypeScript、CSS、HTML、Markdownなどを、プロジェクト自身の`node_modules/.bin/prettier`でフォーマットします。`formatter`設定で、言語ごとにフォーマッタを選べます。
- **Vimモード**（“エディタ › Vimモード”）: ノーマルモード、挿入モード、ビジュアルモード、置換モード、カウント、モーションやテキストオブジェクトと組み合わせるオペレータ、`.`、レジスタ、マーク、マクロ。`u`と⌃Rはエディタの“取り消す”を使い、一続きの挿入は1ステップになります。`"+`と`"*`はクリップボードです。`vimClipboard`設定を使うと、無名レジスタもクリップボードになります。`/`、`?`、`n`、`N`、`*`、`:s`、`:%s`は、Vimのパターンではなく、Rustの正規表現で検索します。`\v`は使えず、`\<`と`\>`の代わりに`\b`を使います。Exコマンドは`:w`、`:q`、`:wq`、`:x`、`:noh`、`:<line>`です。ノーマルモードでは、⌃Gは“行へ移動”ではなくVimに渡ります。
- **設定の同期**（**設定 › 一般**）: iCloud Drive内のフォルダを通じて、設定とキーボードショートカットがほかのMacにも引き継がれます。パス、ローカルアドレス、同意は、それぞれのMacに残ります。

## 言語サーバ

Go、Rust、TypeScriptとJavaScript、Python、C、C++とObjective-C、Swift、シェルスクリプト、JSON、YAML、CSS、HTML、TOML、Markdown、Lua、さらに**設定 › 言語サーバ**で追加した独自のサーバ。Dangoは求めに応じて、サーバを専用のツールフォルダにインストールします。TypeScriptプロジェクト自身の`tsc`が言語サーバとして使える場合は、それを使います。

提供される機能: 診断（⌘'と⇧⌘'で移動）、ホバー（⌃⌘I）、補完（⌥Esc）、シグネチャヘルプ、定義へ移動（⌃⌘J）、型定義と実装、参照（⌃⇧⌘F）、呼び出し階層と型階層（⌃⇧⌘H）、名前の変更（⌃⌘E）、フォーマット（⌥⇧F）、セマンティックカラー、折りたたみ、アウトライン（⇧⌘O）。行内に表示される型とパラメータ名。電球の奥にあるクイックフィックスとリファクタリング（⌥⌘A）。プロジェクトのシンボルは⌥⌘Oで表示します。

ファイル本来のサーバに加えて、ESLintを使うプロジェクトでは、ESLintがJavaScriptとTypeScriptをチェックしてクイックフィックスを提供します。また、HTML、CSS、JSXの補完にはEmmetの省略記法が表示されます。Dangoは求めに応じて両方をインストールします。必要なら、**設定 › 一般**で、保存時にESLintの問題を修正するようにできます。

## ターミナル

ターミナルはタブで開き（**ファイル › 新規ターミナル**、⌃\`）、ログインシェルとその環境で動作します。ターミナルは[Tapa](https://github.com/sventmueller/tapa)のもので、独自のVTコアを持ち、Metalで描画されます。xtermとVT520に対応し、Kittyキーボードプロトコル、OSC 8のリンク、同期出力、トゥルーカラー、マウスレポートをサポートします。文字サイズはエディタと同じで、色はTapaのライトとダークの配色です。zsh、bash、fish用のシェル統合は、設定ファイルに手を触れずに自動で設定され、`ssh`でほかのホストに接続するときにも引き継がれます。再起動後、ターミナルは元のフォルダで新しいシェルとして戻ります（信頼済みのフォルダのみ）。表示していた内容は戻りません。

- **コマンドブロック。** 各コマンドとその出力が1つのブロックになります。⌘↑と⌘↓でプロンプト間をジャンプします。**ブロックを選択**（⇧⌘A）、**出力をコピー**（⌥⌘C）、**出力を保存…**（⌥⌘S）、**ブロックを折りたたむ/展開**（⇧⌘↩）は現在のブロックに作用します。**ブックマークを設定/解除**（⇧⌘M）で行に印を付け、⇧⌘↑と⇧⌘↓でブックマーク間をジャンプします。**コマンドをブロックとして表示**をオンにすると、余白のバーが各ブロックを示し、失敗したコマンドには印が付き、実行中のコマンドは出力がスクロールする間も上部に残ります。ポインタの下にあるブロックの上には、そのステータス、所要時間、同じ操作のボタンが表示されます。
- **ブロックをエージェントに送信**（“編集”メニューとターミナルのコンテキストメニュー）は、新しいAIタブを開き、現在のブロックのコマンドラインと出力を“外部コンテンツ”として添付し（[信頼](#信頼)を参照）、コマンドが失敗した場合は、失敗したCIジョブのログと同じように原因を尋ねる下書きを用意します。`keybindings.json`で`terminal.blockToAgent`にショートカットを割り当てるまで、ショートカットはありません。
- **入力フィールド。** **表示 › 入力フィールドの表示/非表示**（⌘I）で、コマンドラインをターミナル下部のテキストフィールドに変えます。その上にはフォルダとGitブランチが表示されます。新しいターミナルは、最後に選んだ状態に従います。Returnでフィールド全体をシェルに送ります。シェル統合が必要で、vim、htop、claudeなどのフルスクリーンのプログラムでは脇に退きます。
- **提案**は、入力した内容のすぐ後ろにグレイで表示されます。入力フィールドでも、入力フィールドなしでも表示され、各コマンドを実行したときのフォルダ、ブランチ、終了コード付きの履歴、700を超えるコマンドラインツールの仕様、そしてgitブランチ、dockerコンテナ、`package.json`のスクリプト、make、just、cargoのターゲットなどのプロジェクトから提案します。→で提案を確定し、Tabで補完します。候補が複数ある場合はメニューが開き、入力すると絞り込まれます。入力する前に、普段次に来るコマンドをフィールドが提案することもあります。コマンドは部分ごとに色分けされ、シェルが実行できないコマンドには赤い破線の下線が付きます。提案がネットワークを使うことはなく、プログラムを起動するのはログインシェルの`PATH`からだけです。
- **検索**（ターミナルにフォーカスがあるときの⌘F、⌘G、⇧⌘G）は、正規表現、大文字と小文字の区別、単語単位で履歴全体を検索し、検索結果の数を表示します。スクロールバーには、検索結果、プロンプト、失敗したコマンドの位置が示されます。
- **選択とコピー。** ダブルクリックでURL、パス、ハッシュ、IPアドレスをまとめて選択し、⌥ドラッグで矩形を選択します。**キーボードで選択**（⇧⌘C）ではVimのキーで選択範囲を動かし、**書式付きでコピー**（⇧⌥⌘C）は色とスタイルを保ちます。プログラムがOSC 52でコピーできるのは、そのターミナルにキーボードフォーカスがある間だけで、コピーしたことはターミナルが知らせます。クリップボードを読み取れるプログラムはありません。
- **ペースト。** 改行の位置でコマンドが実行されてしまうテキストや、制御文字を含むテキストは、プログラムがブラケットペーストとして読み取る場合を除き、まずシートに表示されます。イメージをペーストすると、ターミナルで実行中のコーディングエージェントに渡され、エージェントがクリップボードから直接読み取ります。そうでなければ、キャッシュに保存したコピーのパスがペーストされます。`ssh`越しでは、そうしない理由をターミナルが知らせます。ターミナルにドロップしたファイルは、イメージも含めて、引用符で囲まれたパスになります。Webページなど、ほかの場所からドロップしたイメージは、ペーストしたイメージと同じように扱われます。
- **リンク。** ⌘クリックで、Webアドレスはブラウザタブで、`mailto:`リンクはメールで、ファイル名は行と列が付いていてもDangoのエディタで開きます。リンクはOSC 8がなくても見つかります。それ以外の種類のリンクは開きません。
- **開発サーバ。** ターミナル内のプログラムが開発サーバを起動すると、ターミナルの上のバーにそのアドレスが表示され、**ブラウザタブで開く**でそこに開きます。
- **通知と進行状況。** ベルと、プログラムが求めた通知（OSC 9とOSC 777）は、ターミナルが見えていない間、そのタブに赤の点を付けます。ほかのアプリが前面にあるときは、通知はmacOSにも送られ、クリックするとターミナルに戻ります。プログラムが報告する進行状況（OSC 9;4）は、タブにはリングとして、Dockのアイコンにはバーとして表示されます。
- **キーボード入力のセキュリティを保護**（**Dango › キーボード入力のセキュリティを保護**）は、ターミナルに入力する内容をほかのアプリが読み取れないようにします。プログラムがパスワードを求めている間も、自動的にオンになります。
- **キー。** ⌘Kでターミナルを消去します（**編集 › ターミナルを消去**）。⌃CとEscは、ターミナル内のプログラムに送られます。ターミナルのコマンドは“編集”メニューと“表示”メニューにあり、そのショートカットはターミナルにキーボードフォーカスがある間だけ働くため、⌘I、⌘↑、⌘Fはエディタでは本来の意味のままです。コンテキストメニューからは、**ここで新規ターミナル**を開いたり、**ペインを閉じる**でターミナルを閉じたりもできます。

**設定 › ターミナル**では、新しいターミナルの入力フィールド、そのVimのキー、提案、コマンドの色分け、不明なコマンドの下線、コマンドブロック、選択範囲のすぐのコピー、複数行のペーストの事前表示、メタキーとしての⌥を切り替えます。

“コンテナ”パネルには、DockerのComposeプロジェクトとそのサービス、単独のコンテナ、イメージ、ボリュームが表示され、Dockerのイベントに合わせてその場で更新されます。フォルダのComposeファイルは、そのコンテナがまだ1つもなくてもプロジェクトとして表示されます。コンテナは起動、停止、再起動でき、ログとシェルはターミナルタブで開き、公開されたポートはブラウザタブで開きます。コンテナ、イメージ、ボリュームの削除と未使用データのクリーンアップは、実行前に確認されます。Composeはプロジェクトに記述された内容をビルドして実行するため、Composeのup、down、pullは信頼済みのフォルダでのみ実行されます。パネルのメニューでは、シェルが使うコンテキストを変えずに、ウインドウのDockerコンテキストを選択できます。同じコマンドは“コンテナ”メニューにもあります。`docker`コマンドラインとDocker 24.0.6以降が必要です。

## Markdown

- **プレビュー。** Markdownファイルは、横にプレビューを表示した状態で開きます。**表示 › 横のプレビューを表示/非表示**（⇧⌘V）でプレビューを閉じたり開いたりでき、**設定 › 一般**で自動プレビューをオフにできます。プレビューには、数式、Mermaid・Graphviz・PlantUMLの図、フォルダ内のイメージが表示されます。Webのイメージが読み込まれるのは、信頼済みのフォルダの場合か、プレビューで読み込みを求めた場合だけです。
- **“フォーマット”メニュー:** 太字（⌘B）、斜体（⌘I）、取り消し線（⇧⌘X）、コード（⌥⇧⌘C）、リンク（⇧⌘K）、見出し1–3（⌥⌘1–⌥⌘3）、箇条書きと番号付きリスト、タスク、引用、コードブロック。各コマンドは選択範囲または行に対してオン/オフを切り替え、1回の操作で取り消せます。
- **ペースト。** WordやWebページのテキストはMarkdownとして、そのイメージは書類の横にファイルとして取り込まれます。⌥⇧⌘Vでプレーンテキストとしてペーストします。
- **書き出し。** **ファイル › 書き出す**で、PDF、イメージを内包した単一のHTMLファイル、またはWord書類に書き出します。Webのイメージが含まれるのは、信頼済みのフォルダから書き出す場合だけです。
- **Splatで開く。** [Splat](https://github.com/sventmueller/splat)がインストールされていれば、**ファイル › Splatで開く**と、ファイルツリーとタブのコンテキストメニューから、書類を保存したうえでSplatで開けます。

## 音声入力

AIタブのメッセージフィールドまたはエディタに音声入力できます。そこにあるマイクボタン、**編集 › 音声入力を開始**（⌃⌥D）、またはfnキー（押し続けて録音、2回押すと録音を続けます）を使います。音声認識は[Lowspeak](https://github.com/sventmueller/lowspeak)のものですが、Lowspeak自体をインストールする必要はありません。

- **設定 › 音声入力**で、モードとモデル（OpenAIまたはGroqでオンライン、WhisperまたはParakeetでローカル）、言語、後処理、マイク、独自の語彙を設定します。
- **ローカルモデル**は、選択したときにHugging Faceからダウンロードされます。進行状況が表示され、キャンセルもできます。モデルはLowspeakが使うフォルダに置かれるので、どちらのアプリも、もう一方がダウンロードしたモデルを使えます。ローカルモデルなら、録音はこのMacから出ません。
- **オンラインの文字起こし**には、OpenAIまたはGroqのキーが必要です。Dangoはこのキーを専用のキーチェーン項目に保管します。
- **Lowspeakから。** Lowspeakがデフォルトと異なる設定になっている場合、“音声入力”タブは、その設定の引き継ぎを一度だけ提案し、求めに応じてキーも引き継ぎます。Dangoがキーを読み込む前にmacOSが確認します（“常に許可”ではなく“許可”を選択してください）。
- **権限。** 最初の音声入力のときに、macOSがマイクへのアクセスを確認します。fnキーは、Dangoがアクティブなアプリで、Lowspeakが実行されていないときに使えます。fnキーには“アクセシビリティ”の権限が必要で、Dangoはそれを最初の音声入力のあとに求め、起動時に求めることはありません。

## 信頼

フォルダは、その中で何かが起動されるとすぐにプログラムを実行させることができます。Gitのフックや`core.fsmonitor`などのリポジトリ設定、`node_modules`の言語サーバ、エージェントのフック、`.mcp.json`です。フォルダを初めて開くと、Dangoはそのフォルダを信頼するかどうかを尋ねます。

- **信頼済み:** Git、言語サーバ、デバッガ、エージェント、CIが、このフォルダとその下にあるすべてに対して動作します。
- **制限付き:** 読み込みと編集はできます。エディタの変更マークは、`.git`を直接読み込んで表示します。フォルダで設定されたものは何も起動されません。Git、CI、AIの各パネルはそのことを示し、フォルダを信頼するよう提案します。

自分以外から来たテキストには、エージェントを操るための指示が含まれていることがあります（プロンプトインジェクション）。そのため、ターミナルの出力（`@terminal`、またはエージェントに渡したコマンドブロック）、ブラウザのページ（`@browser`）、エージェントに渡されたCIログ、プロジェクト外のファイル、Webページからペーストした長めのテキストは、印を付けて渡されます。チップには“外部コンテンツ”と表示され、エージェントは、信頼できないデータでありその指示に従ってはならないという注意書きとともにテキストを受け取ります。内蔵エージェントが取得したWebページにも、同じ注意書きが付きます。ペーストしたテキストは、Safari、Chrome、Firefoxのように、ブラウザがクリップボードでそう示している場合に、Webページからのものとみなされます。それ以外の場所からのテキストや、数語程度の短い語句は、ユーザ自身のものとして扱われます。

## サンドボックス

Dango自体はApp Sandboxなしで動作します。Dangoが起動するすべてのプログラムにサンドボックスが引き継がれ、ターミナル、Git、言語サーバ、エージェントが動作できなくなるからです。その代わりに、各AIスレッドにはサンドボックスのスイッチがあり、デフォルトではオフです。何が制限されるかはエージェントによって異なり、スイッチのツールチップにその内容が表示されます。

| エージェント | サンドボックスがオンのとき |
|---|---|
| Claude | シェルコマンドはClaude自身のサンドボックスで実行されます。ファイルとWebのツールは対象外です |
| Codex | コマンドと変更による書き込みはプロジェクト内に限られ、ネットワークは使えません |
| 内蔵エージェント | ファイル、Webリクエスト、コマンドはプロジェクトと許可したフォルダの中にとどまり、ネットワークは使えません（`sandbox-exec`） |
| Antigravity、OpenCode | Dangoがオンにできるサンドボックスはありません |

## 外観とアクセシビリティ

- **ダークモード**はシステムに従います。**コントラストを上げる**と**視差効果を減らす**の設定も反映されます。
- **VoiceOver**は、サイドバー、タブ、AIタイムラインのカード、GitとCIの行、デバッガを名前付きで読み上げ、ターミナルの行を読み上げて新しい出力を知らせます。ブレークポイントを色だけで区別することはありません。
- **キーボード。** すべてのコマンドにショートカットがあり、どれも`keybindings.json`で変更できます。⌥⌘\`で次のパネルに移動します。
- **右から左。** アラビア語とヘブライ語ではウインドウが左右反転しますが、コード表示とターミナルのグリッドは左から右のままです。

DangoがAppKitに加えている内容は、分野ごとに[ACCESSIBILITY.md](../../../ACCESSIBILITY.md)に記載されています。

## プライバシーとセキュリティ

- **テレメトリなし。** 解析も、どこかへ送信されるクラッシュレポートもありません。エラーはシステムログ（“コンソール”アプリで、アプリ名の下）に記録されます。
- **ネットワークを使うのは、ユーザが開始したものだけです。** 使用するエージェント（それぞれ自身のサービスと通信します）、求めたときのACPレジストリと、エージェント、言語サーバ、デバッグアダプタ、音声入力モデルのダウンロード、サインインしたCIホスト、選択した場合のCopilotによる編集の予測、内蔵エージェントのプロバイダ、選択した場合のオンライン文字起こし、ブラウザタブで開いたページ、そして許可したあとのアップデート確認です。
- **コードがMacの外に出る**のは、そのためのサービスを選んだ場合だけです。エージェント、Copilotの予測、AIが書くコミットメッセージがそれにあたります。コミットメッセージのための差分が送信されるのは、gitleaksがその中にシークレットを見つけなかった場合だけです。
- **キーとトークン**はmacOSのキーチェーンに保管され、設定ファイルに書かれることはありません。Lowspeakなどほかのアプリのキーは、同意した場合にだけ、しかも一度だけ読み込まれます。
- **固定されたダウンロード。** Dangoがインストールするエージェント、言語サーバ、デバッグアダプタはテスト済みのバージョンに固定され、チェックサムで検証されます。
- **コード署名**にはHardened Runtimeを使います。アップデートは、アプリ独自の署名がある場合にだけインストールされます。

## データの保存場所

`<id>`はバンドルIDで、リリース版では`local.agentide`（デバッグビルドでは`local.agentide.debug`）です。表示名を含まないため、名前が変わってもすべてのデータが保たれます。

| 場所 | 内容 |
|---|---|
| `~/Library/Application Support/<id>/` | `settings.json`、`state.json`、`keybindings.json`、`trust.json`、`terminal-history.sqlite`（ターミナルのコマンド履歴）。`threads/`（AIパネルのリスト）、`agent-threads/`（内蔵エージェントの会話）、`layouts/`（プロジェクトごとのタブ）、`recovery/`（クラッシュ後の未保存のエディタ）、`checkpoints/`（Gitのないフォルダ用）、`worktrees/`、`agents/`と`tools/`（インストールされたエージェント、言語サーバ、デバッグアダプタ）、`task-output/` |
| `~/Library/Caches/<id>/` | ペーストしたイメージ、シェル統合スクリプト、ACPレジストリ。削除してもかまいません |
| `~/Library/Logs/<id>/dictation/` | 音声入力のログファイル |
| `~/Library/Application Support/Lowspeak`と`FluidAudio` | ローカルの音声入力モデル。Lowspeakと共有します |
| `~/Library/WebKit/<id>/` | ブラウザタブのCookieとWebサイトデータ |
| `<project>/.dango/settings.json` | プロジェクト独自の設定 |
| プロジェクトのGitリポジトリ | チェックポイント。`refs/ide-checkpoints/`以下のコミットとして保存され、通常のプッシュやフェッチで送受信されることはありません |
| キーチェーン、サービス`<id>` | 内蔵エージェントと音声入力のAPIキー、CIのトークン |
| `~/.local/bin/dango` | ターミナルコマンド（インストールした場合） |

Claudeは自身のセッションを`~/.claude/projects`以下に保存します。Dangoはセッションを再開するためにそれを読み込みますが、変更はしません。

## 既知の制限

- **アプリ自体にApp Sandboxはありません。** ターミナル、Git、言語サーバ、エージェントに引き継がれてしまうためです。フォルダで設定されたものが実行されるのは、そのフォルダを信頼したあとです。AntigravityとOpenCodeには、Dangoがオンにできるサンドボックスがありません。
- **Claudeの使用量の数値とコンテキストの内訳**は、プロトコルのうち試験的とされている部分に依存しており、その部分がない場合は表示されません。
- **会話の巻き戻し**はClaudeでのみ使えます。ほかのエージェントでは、コードだけが巻き戻されます。
- **ブラウザ経由のCIへのサインイン**はオフになっています。`gh`、`glab`、トークン、または環境変数を使ってください。
- **ターミナル内にイメージは表示されません。** Kittyグラフィックス、Sixel、iTerm2のイメージには対応していません。
- **Gemini CLIは提供していません。** Googleが個人アカウントでのサインインを終了し、Antigravityを案内しているためです。以前のGeminiスレッドは引き続き読めます。

## ソースからのビルド

必要なもの:

- Xcode Command Line Tools（`xcode-select --install`）がインストールされたmacOS 14以降。Xcode自体は不要です。
- `rust-toolchain.toml`で指定されたバージョンのRust。Homebrewの`rust`はこのMacのプロセッサ向けにビルドします。リリースのユニバーサルビルドには、ターゲット`aarch64-apple-darwin`と`x86_64-apple-darwin`を追加したrustupが必要です。
- [splat](https://github.com/sventmueller/splat)、[lowspeak](https://github.com/sventmueller/lowspeak)、[tapa](https://github.com/sventmueller/tapa)のチェックアウトを、このリポジトリの隣（`../splat`、`../lowspeak`、`../tapa`）に置き、それぞれ`main`ブランチにしておくこと。ワークスペースはそれらからクレートをパスで取り込み、ターミナルはTapaから取り込みます。
- cmake。音声入力を含むすべてのビルド（`make run`、`make build`、`make release`）で、whisper.cppのビルドに使います。`make check`はcmakeなしでビルドできます。

| コマンド | 内容 |
|---|---|
| `make run` | デバッグ版アプリ（`target/debug/Dango Debug.app`）をビルドして開きます |
| `make build` | リリース版アプリ（`target/release/Dango.app`）をビルドします。最初のビルドで“ログイン”キーチェーンに作成されるローカル証明書で署名し、`Cargo.toml`は変更しません |
| `make lint` | フォーマットとclippy。警告があると失敗します |
| `make check` | `lint`のあと、すべてのテスト。キーチェーン、ウインドウ、ネットワークは不要です |
| `make test` | `check`のあと、実際のアプリで、セルフテスト`probe`とアクセシビリティ監査を、左から右と右から左の両方で実行します |
| `make perf` | リリースビルドでの時間予算の計測。ほかに何も動いていないMacでのみ意味があります |
| `make release` | `target/release-dry-run/`へのリリースのドライラン。ローカル証明書で署名し、どこにも何も送信しません |
| `make release-notarized` | `check`のあと、`dist/`への実際のリリース。Developer ID署名、公証、アプリ独自の鍵で署名したアップデートフィード。`Cargo.toml`は変更しません |
| `make deploy` | 変更が残っていない`main`で、CIシールの有無を問わず、次のバージョンを公証し、`Cargo.toml`をコミットします。リリースファイルをアップロードし、コードとバージョンタグを（緑のCIシールがあればそれも）プッシュしてから、リリースを自ら公開します |

デバッグ版とリリース版は、それぞれ独自の設定とデータを持つ別々のアプリです。ビルド、テスト、セルフテスト、リリース、コードが従うルールは[docs/development.md](../../../docs/development.md)に、その背景にある決定事項は[docs/plan.md](../../../docs/plan.md)に記載されています。リリースノートは[RELEASE_NOTES.md](../../../RELEASE_NOTES.md)で、各READMEの隣の`assets/readme/<language>/`に翻訳があります。
